# **基础**

## **路径**

### **基本名**

1.~用户文件               /home/user

2.系统目录                 /etc

3.程序与库                 /usr

4.日志等可变数据      /var

5.设备文件                  /dev

tips:路径大小写敏感；~ 是当前用户的家目录，. 是当前目录，.. 是上一级，/是根目录

### **几种路径**

绝对路径：从 / 开始                     /home/user/example

相对路径：从当前位置开始         ./hello.txt      

home目录中的 example             ~/example

相对路径以当前位置为起点，即当输入 `cd example` ，系统是在***目前所在的文件夹里面***找 `example` 这个文件夹并进入。

（程序都是靠目录来调的）

### **重定义**

重定义

< 键盘输入

1>  正常的运行结果（平时屏幕上看到的字）输出

2>  程序报错的输出

/dev/null  垃圾桶（用 > 放进去）

（可以多个连用，按顺序走）

A.py >> B.txt 2>&1

cat >>A.yaml << EOF

$(xxx)

$(tail -n 10 path）

EOF

这是EOF前的所有加入到A.yaml

区分好>>和>的区别!

## **git**

先自己add,commit 只记录到本地仓库；push 才把提交发送到远程。

姓名与邮箱会写入提交记录

git config --global user.name "Your Name"

git config --global user.email "you@example.com"

提交作者信息

SSH 认证

| git clone <仓库地址> | 下载仓库及提交历史     |
| -------------------- | ---------------------- |
| `git status`         | 查看当前分支和文件状态 |
| `git diff`           | 查看尚未暂存的修改     |
| `git log --oneline`  | 用简短格式查看提交历史 |

---

| 命令                               | 说明                         |
| :--------------------------------- | :--------------------------- |
| `git switch -c feature/hello`      | 创建并切换到功能分支         |
| `git add hello.txt`                | 暂存指定文件                 |
| `git commit -m "Add greeting"`     | 记录一次本地提交             |
| `git push -u origin feature/hello` | 推送并建立跟踪关系           |
| `git switch main`                  | 切回主分支                   |
| `git pull`                         | 获取并整合当前分支的远程更新 |

---

1：在错误的分支上疯狂输出
忘了建分支在 main 上改！

· 补救办法：先别 commit。敲 git switch -c feature/my-new-branch。Git 会把你现在还没提交的修改，全部带到新分支上去。主分支就安全了。

2：分支名乱起
分支名不能是中文，不要带空格。团队一般有规范。
