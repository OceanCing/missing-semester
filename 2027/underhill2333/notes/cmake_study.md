## CMake和Catkin

### CMake

- CMake是为了解决复杂工程问题而发明的工具，相比makefiles可以跨平台。总流程CMakeLists.txt --- (cmake命令) ---> Makefile --- (make命令) ---> 可执行文件

- CMakelists.txt的作用：就是怎么编译文件去生成可执行文件的总指挥。要注意大小写，要不系统不认

> AI学习记录*我这里让AI给我一道练习题，它给了我一道关于云台角度的问题，我想以此来具体化各种概念，要不仅仅是记各种知识点就很困难了.它出的练习题是一道跟云台有关的角度换算工具，代码不用我写，但我要把源码文件给组装起来*

> 第一步编写头文件时我就卡住了，原因是对整个CMakeLists的结构不熟悉，下面是我总结的最简单的CMakeLists的结构

- 首先是固定开头和项目名，然后是要造的东西，程序用 add_executable，库用 add_library，缺头文件路径就补 target_include_directories，缺函数就补 target_link_libraries

> 我这里是先造了项目再造材料，逻辑上明显不对,这是一个坑，也就是编写CMakeLists时要注意逻辑顺序

- 文件夹名字含义
1.scr里装的是源码源文件
2.build里装的是makefile和其他中间过程的文件
3.sev里装的是生成好的可执行文件

> *在这里CMakeLists.txt时，漏写了目标名，还有头文件拼错了，然后cmake时报错，我让AI老师教我怎么识别报错类型，然后我就懂得了一些基本的报错类型

- 报错01
1.CMake Error
图纸阶段。还没开始编译，源码根本没被碰过。
2.error: …
施工阶段。已经在编译源码了。

> 这里AI老师先让我不拆库，然后再让我拆库，我就对拆和不拆有了一个认识

- 不拆库
不拆库就是什么东西都放一起，编译的时候`add_executable(gimbal src/main.cpp src/gimbal_math.cpp)`是这样几个放程序到一起

- 拆库
拆库就是把包，程序什么的按功能分开放，然后后运行时把各个代码头文件链接起来，统一通过main函数实现`add_executable(gimbal src/main.cpp)`

> 我在通过拆库的时候，也发现了PUBLIC在拆库是必须要用，在单程序时可用可不用。因为这样才能传递头文件

- PUBLIC 
PUBLIC主要干了两件事，给文件挂上信息，1.头文件在哪里2.代码在哪里

> 这里AI老师给我做了个实验，让我把链接注释掉，让我通过报错来认识两种新的报错类型。

-报错类型02
1.fatal error: … No such file

解法：补路径
2.undefined reference to …
链接期。文件都编好了，拼不起来。

- source（AI的解释，帮助理解我在干啥）
source 不是开机，是「把工具箱搬进这间屋子」。它执行一个 bash 脚本，里面全是 export XXX=路径。跑完，你这个终端就记住了：ROS 的工具在哪、库在哪、包在哪。

关键：这些变量只活在「当前这个终端」。你新开一个终端 = 一个新的空抽屉，什么都没搬进去。

所以不是「打开 ROS」，而是每个新终端都要自己搬一次。这是它和「启动服务」最大的区别。

- 三个命令的含义
source setup.bash
设置：改环境变量，瞬间完成，不启动任何东西
catkin_make
编译：真的调编译器，生成 build/ 和 devel/ 里的文件
roscore
运行：真的起一个进程（服务器），要一直开着
AI总结：只有第三个才叫「打开」。source 是准备工作，catkin_make 是生产，roscore 才是开张营业。

## 程序的编译流程(知乎专栏)

> 使用AI学习过程记录 *在学习这部分知识的时候，有很多看不懂的专业术语(比如宏处理)，于是我想借助Deepseek来给我解释一下，但我发现一个个名词让它解释太费劲，然后我想把整个难懂的文章喂给她修改成能看的，发现它没法打开有反爬的网站。于是想能不能在deepseek harness搞一个爬取像知乎这类网站的插件，发现是用最贵的方式来获取信息，不如直接用Ctrl+p来把网页转为PDF再喂给AI。这个Ctrl+p是在和AI的交流中才发现有这么个好用的快捷键，这我认为是借助大模型学习的好处之一，在和AI的交流过程中，因为AI的知识面极为广阔，你在和AI的交流过程中往往能得到其他有用的知识。*



- 程序的编译主线
  hello.c（文本）→ 预处理 .i（文本）→ 编译 .s（汇编文本）→ 汇编 .o（二进制可重定位目标文件）→ 链接 可执行文件（二进制）

- 预处理（产物i）
  按 # 指令把文本改一遍。它不懂 C 语言语法，只在字符层面做替换和粘贴。就是把人话初步翻译为机器语言，AI给了一个合适的比喻，可以把源代码想象成中文写的菜谱——厨师（程序员）看得懂，但厨房里的机器（CPU）不认中文。
  
> 这里跟前面的报错有关fatal error: xxx.h: No such file,没有头文件也就没办法编译文件

###名词解释
  宏：纯文本替换。写 #define N 100，之后代码里每个 N 都被换成 100。
  声明：告诉编译器有这么个东西，长什么样
  定义：分配空间，实现储存功能

- 编译（产物s）
  把一个源文件翻译成汇编代码。下面是AI给出的比喻你可以把编译器理解为一个精通中英双语的翻译官，把中文菜谱翻译成英文菜谱，供后面的“炒菜机”阅读。（汇编语言太复杂了我就了解一下就溜了）

> 这里跟我前面翻过错误也有关，例如在编写源文件时漏了l;或者变量没加数据类型等，都会导致对源文件的编译失败

###名词解释
  汇编语言：比机器码好读一点点的人类可读版机器指令，一条汇编通常对应一条 CPU 指令。寄存器就是 CPU 手里那几个极快的临时格子。

- 汇编（产物o）
  把汇编代码逐条翻译成机器码，打包成目标文件。此时的汇编语言已经很硬件了。

名词解释
  机器码 / 指令集：CPU 真正能执行的二进制指令。指令集就是这个 CPU 的「方言表」，x86 和 ARM 说的话不一样——所以同一个程序换架构就得重新编译。
  交叉编译：在 x86 电脑上编译出 ARM 板子能跑的程序。做嵌入式时才需要。

> 链接部分在CMake和catkin里经常遇到，就是在写CMakeLists.txt部分链接链接的就是o.文件，在CMakeLists.txt里写链接写错时就会报错undefined reference to …

- 链接
  机器码已经搞好了（o文件），然后把o文件拼成一个可执行文件。拼接零件和接上外部库。

名词解释
  库：就是别人提前*编译*好的一堆代码或者函数，然后打包给你用。比如C语言中的prinf，prinf的实现不是你来写，就是人家已经写好在标准库里。其实就是造好的工具
  静态库：链接时，链接器会从静态库里只挑出你用到的那些目标模块，复制进最终可执行文件。不是整个库无脑塞进去，但用到的部分会被“焊死”进程序。
  共享库：共享库不是复制进你的可执行文件，而是：可执行文件里只记录“我需要某个库里的某个函数”，运行时由系统把共享库加载进内存，大家共用。

## 菜鸟教程

> 第一次看这个菜鸟教程我感觉就是在看天书，就是如果没有AI来给我解释，我不知道要看多久才能看懂

- CMake基础

> 前面那几个指令太常用了，我觉得再放进来就显得很啰唆，所以这里我主要记下那些我在学习CMake和catkin没见过的指令

- 添加库文件：
实例
 语法：add_library(<目标名> [STATIC | SHARED | MODULE] <源文件>...)
 STATIC：静态库（.a / .lib），编译时直接嵌入可执行文件
 SHARED：动态库（.so / .dll），运行时加载
 不指定类型时，由 BUILD_SHARED_LIBS 变量决定
add_library(MyLib STATIC library.cpp)

-设置变量
 语法：set(<变量名> <值>...)
 定义一个普通变量，后续通过 ${变量名} 引用
set(CMAKE_CXX_STANDARD 17)

 同时设置多个值（列表）
set(SOURCES main.cpp utils.cpp helper.cpp)
add_executable(MyApp ${SOURCES})

- 条件语句
 语法：if(<条件>) ... elseif(<条件>) ... else() ... endif()
 CMake 支持的条件表达式包括：比较、逻辑运算、变量判断等
if(CMAKE_BUILD_TYPE STREQUAL "Debug")
    # Debug 模式下启用调试信息
    message(STATUS "当前为 Debug 构建模式")
    set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -g")
else()
    # Release 模式下启用优化
    message(STATUS "当前为 Release 构建模式")
    set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -O2")
endif()

- 自定义命令
 语法：add_custom_command(
         TARGET <目标>
          PRE_BUILD | PRE_LINK | POST_BUILD
          COMMAND <命令> [参数...]
          [COMMENT <说明>]
          [VERBATIM])
 PRE_BUILD：在编译前执行
 PRE_LINK：在链接前执行
 POST_BUILD：在构建完成后执行
add_custom_command(
    TARGET MyApp POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E echo "构建完成！"
    COMMENT "打印构建完成信息"
)
