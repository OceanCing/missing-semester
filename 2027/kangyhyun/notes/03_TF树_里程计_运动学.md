# ROS1 学习笔记 3：TF 树、里程计与麦轮运动学


调用顺序：`/cmd_vel → 逆运动学 → 轮速 → PID → 力矩 → Gazebo → 实际轮速 → 正运动学 → 里程计 → TF`。

## 1. 三个坐标系

```
map       地图/世界坐标系-> 地图上的绝对位置->跟导航有关
odom      里程计坐标系->从起点开始累计的里程->跟轮式里程计有关
base_link 车体坐标系->车自己的前后左右->跟车体本身有关
```

## 2. TF 树

### 2.1 TF 树的形状

```text
map
 └── odom
      └── base_link
           ├── left_front_wheel
           ├── right_front_wheel
           ├── left_back_wheel
           └── right_back_wheel
```

TF 的箭头方向是：

父坐标系 -> 子坐标系 即父坐标系中的点，通过变换，表示到子坐标系

### 2.2 谁发布哪一段


- `map -> odom`用于定位/导航 
- `odom -> base_link`  `HeroChassisController`  计算里程计位姿 
- `base_link -> 四个轮子`  `robot_state_publisher` 根据 URDF 和 `/joint_states` 调用

`robot_state_publisher` 的输入是：

```
URDF 中的关节位置关系
/joint_states 中的关节角度
```

**注意**:它不是控制器，不参与 PID，只负责发 TF。

## 3. TF 的代码：发布和查询

### 3.1 发布 `odom -> base_link`

```cpp
tf::Transform trans;
trans.setOrigin(tf::Vector3(pos_x, pos_y, 0.0));
##设置平移：车在 odom 坐标系的 `(x, y)`。
trans.setRotation(tf::createQuaternionFromYaw(pos_yaw));
##设置旋转：把 `yaw` 角度变成四元数。
tf_broadcaster.sendTransform(
    tf::StampedTransform(trans, time, odom_frame, base_frame));
##在 time 时刻，base_link 相对 odom 的位姿是 trans
```

### 3.2 查询 TF

终端：

```
rosrun tf tf_echo odom base_link
```

输出：

```
Translation: [x, y, z]
Rotation: [x, y, z, w]
```

看 TF 树：

```
rosrun tf view_frames
evince frames.pdf
```

### 3.3 把速度从 odom 转到 base

世界系速度模式里：

```cpp
##
输入：odom 坐标系下的线速度
目标：base_link 坐标系下的线速度
geometry_msgs::Vector3Stamped in;
geometry_msgs::Vector3Stamped out;

in.header.frame_id = odom_frame;
in.header.stamp = ros::Time(0);
in.vector = msg->linear;

tf_listener.transformVector(base_frame, in, out);
```

为什么要这样做？

因为 `/cmd_vel` 默认可以理解为“车头方向的速度”。如果 `world_frame_mode=true`，它就变成“场地方向的速度”，需要先通过 TF 转到车体方向，再送入逆运动学。

### 3.4 `ros::Time(0)` 是什么意思

```cpp
##使用当前最新的 TF
in.header.stamp = ros::Time(0);
```
**注意**:这并不是严格按某个历史时刻查询。简化写法能跑，但启动瞬间 TF 还没发布时可能拿不到，所以前几条指令可能失败。

## 4. 麦克纳姆轮逆运动学

### 4.1 输入输出
通过输入：

```
vx      前进速度
vy      左右速度
wz      旋转角速度
```

输出：

```
四个轮子的目标角速度
```

### 4.2 公式

```cpp
k = (wheel_base + wheel_track) / 2;

v_lf = (vx - vy - k * wz) / r;
v_rf = (vx + vy + k * wz) / r;
v_lb = (vx + vy - k * wz) / r;
v_rb = (vx - vy + k * wz) / r;
```
参数：
```
wheel_base  = 0.4
wheel_track = 0.4
k           = (0.4 + 0.4) / 2 = 0.4
r           = 0.07625
```

### 4.3 符号表

轮序：

```
[0] 左前 LF
[1] 右前 RF
[2] 左后 LB
[3] 右后 RB
```

| 指令 | 左前 | 右前 | 左后 | 右后 |
|---|---:|---:|---:|---:|
| 前进 `vx > 0` | + | + | + | + |
| 左移 `vy > 0` | − | + | + | − |
| 逆时针 `wz > 0` | − | + | − | + |

不用死背。比如左移时令 `vx=0, wz=0`，只看 `vy`：

```
v_lf = -vy / r     负
v_rf = +vy / r     正
v_lb = +vy / r     正
v_rb = -vy / r     负
```

### 4.4 前进的数值

```
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.2}}'
```

四个轮子轮子速度：

```
0.2 / 0.07625 ≈ 2.62 rad/s
```

### 4.5 轮速限幅

```cpp
##把目标轮速限制在 [-50, +50] rad/s
speed[0] = std::max(-max_wheel_speed,
                    std::min(max_wheel_speed, speed[0]));
```

**注意**:如果指令非常大，没有这个限制，轮子可能飞转。

## 5. 正运动学：轮速反推车速

### 5.1 公式

```
vx = r * ( LF + RF + LB + RB ) / 4
vy = r * ( -LF + RF + LB - RB ) / 4
wz = r * ( -LF + RF - LB + RB ) / (4 * k)
```

这里的 `LF/RF/LB/RB` 是四个轮子的实际角速度，来自：

```cpp
joint_lf.getVelocity();
joint_rf.getVelocity();
joint_lb.getVelocity();
joint_rb.getVelocity();
```

### 5.2 为什么要用实际速度

`/cmd_vel` 是“想要的速度”。

轮子可能出现以下情况：
- 还没跟上目标
- 被地面卡住
- 打滑
- 负载太大
**注意**:如果直接用指令速度积分，里程计会“以为车到了”，但实际没到。用实际轮速反推，更接近真实运动。

## 6. 里程计

### 6.1 里程计不是定位

里程计只根据轮子转速和运动模型估计位姿，没有地图匹配，也没有绝对参考。

```
里程计 = 从起点开始累计
定位   = 在地图中找到绝对位置
```

### 6.2 速度积分成位姿

```cpp
pos_x = pos_x + (vx * std::cos(pos_yaw)
                 - vy * std::sin(pos_yaw)) * d;
pos_y = pos_y + (vx * std::sin(pos_yaw)
                 + vy * std::cos(pos_yaw)) * d;
pos_yaw = pos_yaw + wz * d;
```

`d` 是 `dt.toSec()`，也就是一个控制周期的时间。

### 6.3 为什么需要旋转

车身速度：

```
vx 向前
vy 向左
```

世界坐标：

```
x 轴固定
y 轴固定
```

如果车头转了 90°，车身的“向前”就不再是世界坐标的“+x”。所以要先按 `yaw` 旋转，再累加。

### 6.4 `/odom` 消息

```cpp
nav_msgs::Odometry odom;
odom.header.stamp = time;
odom.header.frame_id = odom_frame;
odom.child_frame_id = base_frame;

odom.pose.pose.position.x = pos_x;
odom.pose.pose.position.y = pos_y;
odom.pose.pose.orientation =
    tf::createQuaternionMsgFromYaw(pos_yaw);

odom.twist.twist.linear.x = vx;
odom.twist.twist.linear.y = vy;
odom.twist.twist.angular.z = wz;

odom_pub.publish(odom);
```

字段：

| 字段 | 含义 |
|---|---|
| `header.frame_id` | `odom` |
| `child_frame_id` | `base_link` |
| `pose.pose.position` | 位置 |
| `pose.pose.orientation` | 姿态四元数 |
| `twist.twist.linear` | 线速度 |
| `twist.twist.angular` | 角速度 |

### 6.5 协方差

`nav_msgs/Odometry` 里的协方差通常是 6×6 矩阵：

```
pose.covariance    位姿估计的不确定度
twist.covariance   速度估计的不确定度
```

协方差大：

```
我不太确定
```

协方差小：

```
我比较确定
```
### 6.6 里程计漂移

原因：
- 轮子打滑
- 轮半径不准
- 轮距不准
- 地面摩擦变化
- 积分累积

### 6.7 为什么里程计要发布 TF

`/odom` 是给程序读的数据，TF 是给坐标变换系统用的。两者表达的是同一组位姿：

```text
/odom 的 position  ≈  tf 的 translation
/odom 的 orientation ≈ tf 的 rotation
```
可以用：

```
rostopic echo /odom
rosrun tf tf_echo odom base_link
```

对照看两者是否一致。

## 7. 世界系速度模式

### 7.1 两种理解

车身系：

```
linear.x = 沿车头方向走
```

世界系：

```
linear.x = 沿 odom 的 +x 方向走
```

### 7.2 运行流程

```
/cmd_vel
  
如果 world_frame_mode = true
  
用 TF 查 odom -> base_link
  
transformVector 把速度转到 base_link
  
再送逆运动学
```

### 7.3 实验方法

1. 先让车原地转 90°。
2. 再发 `linear.x = 0.2`。
3. 车身系模式：车朝新车头走。
4. 世界系模式：车沿原 odom +x 方向走。

注意：启动瞬间 TF 可能还没准备好，先等 1 秒再发。

## 8. 总结
 逆运动学把 `/cmd_vel` 变成四个轮子的目标速度，PID 让轮子追上目标；正运动学再用实际轮速反推车速，积分得到 `odom` 位姿，最后同时发布 `/odom` 和 `odom -> base_link` 的 TF。
