# ROS 架构与通信学习笔记

## 一、ROS 基础

### 1. 什么是 ROS？

ROS（Robot Operating System）是一个开源的机器人软件框架，提供通信机制、开发工具以及大量机器人相关的软件包。

ROS 并不是传统意义上的操作系统，更像是运行在 Linux 之上的机器人中间件和工具箱。

ROS 主要提供：

- 通信机制：实现不同节点之间的数据交换。
- 开发工具：编译、启动、调试和可视化。
- 软件生态：可以使用现有的传感器驱动、算法库等。

本次课程主要介绍 ROS 1 Noetic。

### 2. 为什么使用 ROS？

机器人通常需要同时完成视觉识别、运动控制、传感器数据处理等任务。

如果把所有功能写在一个程序里，代码会越来越复杂，也不方便多人合作。

ROS 可以将不同功能拆分成独立节点，通过统一的通信机制进行协作。

另外，ROS 提供 rviz、rqt、rosbag 等工具，方便可视化、调试以及数据回放。

## 二、ROS 系统架构

### 1. ROS 的三层架构

ROS 可以从三个层面理解。

**文件系统层**

负责组织代码和配置文件，主要包括工作空间、功能包以及功能包中的各种文件。

**计算图层**

负责描述程序之间的协作关系。

主要包含五个概念：

- Node：节点，执行具体任务的进程。
- Topic：话题，节点之间传输连续数据的通道。
- Message：消息，规定传输数据的结构。
- Service：服务，用于请求和应答。
- Parameter：参数，用于存储配置。

**通信层**

负责节点之间实际的数据传输，包括建立连接、消息序列化等。

### 2. ROS Master

ROS Master 主要负责节点和通信资源的注册、查询，以及参数服务器相关功能。

例如节点 A 发布 `/cmd_vel`，节点 B 需要订阅这个话题。

通信过程可以概括为：

1. 使用 `roscore` 启动 Master。
2. 发布者向 Master 注册话题。
3. 订阅者向 Master 查询发布者。
4. Master 将发布者的地址提供给订阅者。
5. 订阅者与发布者建立连接。
6. 双方直接传输数据。

**需要注意的是，实际的话题数据不经过 Master。**

Master 主要负责帮助节点找到彼此。

## 三、ROS 的三大通信机制

### 1. Topic 话题通信

Topic 使用发布/订阅模式，适合连续的数据传输。

例如：

- 相机持续发布图像。
- 编码器持续发布速度。
- 控制器持续发布运动指令。

主要特点：

- 异步通信。
- 支持多个发布者和订阅者。
- 发布者不需要等待订阅者处理完成。
- 消息类型必须匹配。

常用命令：

`rostopic list`：查看话题列表。

`rostopic echo /topic`：查看指定话题的数据。

`rostopic info /topic`：查看发布者和订阅者。

`rostopic hz /topic`：查看话题发布频率。

### 2. Service 服务通信

Service 采用请求/应答模式。

客户端发送请求，服务端处理后返回结果。

适用于：

- 切换机器人工作模式。
- 请求执行一次初始化。
- 清除已有轨迹。
- 执行一次特定操作。

Service 通常是同步调用，客户端需要等待结果，因此不适合直接承担高频、持续的数据传输。

### 3. Parameter 参数服务器

参数服务器用于保存机器人的配置信息。

例如：

- PID 参数
- 电机速度限制
- 相机参数
- 控制阈值

常用命令：

`rosparam list`：查看所有参数。

`rosparam get`：读取参数。

`rosparam set`：修改参数。

`rosparam load`：从 YAML 文件加载参数。

### 4. 三种通信方式的区别

| 通信方式 | 特点 | 适用场景 |
|---|---|---|
| Topic | 异步、连续传输 | 速度、位置、图像 |
| Service | 请求与应答 | 初始化、模式切换 |
| Parameter | 存储配置 | PID、阈值、限位 |

我的理解是，三种方式并不是相互替代的，而是针对不同需求进行分工。

机器人运行过程中不断变化的数据适合使用 Topic，而偶尔执行一次的操作适合 Service。需要统一管理的配置则适合放在 Parameter Server 中。

## 四、ros_control 控制框架

### 1. ros_control 是什么？

ros_control 是 ROS 1 中用于实现机器人控制的框架。

它将控制算法与底层硬件访问分离，使控制器不必直接处理每一种电机的通信协议。

主要包含：

- Controller：控制器
- RobotHW：硬件接口
- Controller Manager：控制器管理器

### 2. Controller

Controller 负责实现具体的控制算法，例如：

- PID 控制
- 位置控制
- 速度控制
- 轨迹控制

控制器根据目标值和反馈值计算控制输出。

### 3. RobotHW

RobotHW 负责连接控制器与实际硬件。

主要涉及两个函数：

`read()`：读取电机位置、速度等反馈信息。

`write()`：将控制器计算的指令发送给硬件。

例如控制器输出目标电流后，RobotHW 可以通过 EtherCAT 或 CAN 通信链路将指令发送给电机。

### 4. Controller Manager

Controller Manager 负责管理控制器，包括加载、启动、停止和切换。

### 5. 我的理解

我认为 ros_control 最重要的思想是将控制算法与硬件接口解耦。

例如，原本使用 CAN 通信的电机更换成另一种型号时，如果 RobotHW 接口保持一致，理论上可以尽量减少对上层控制器的修改。

同样，更换 PID 控制器或轨迹控制算法时，也不一定需要重新设计底层通信。

可以简单理解为：

**Controller 负责计算，RobotHW 负责数据收发，底层硬件负责执行。**

这种分层方式有利于代码维护，也方便团队协作。

## 五、ROS 文件系统与功能包

### 1. 工作空间

典型 Catkin 工作空间包含：

- `src/`：存放功能包源代码。
- `build/`：存放编译中间文件。
- `devel/`：存放开发阶段生成的程序、库和环境配置。

### 2. ROS 功能包

一个功能包中常见的文件包括：

- `package.xml`：记录功能包信息及依赖。
- `CMakeLists.txt`：描述编译规则。
- `src/`：存放 C++ 源文件。
- `include/`：存放头文件。
- `msg/`：定义自定义消息。
- `srv/`：定义自定义服务。
- `launch/`：存放启动配置。
- `config/`：存放 YAML 参数文件。

其中 `package.xml` 和 `CMakeLists.txt` 是两个非常重要的配置文件。

## 六、YAML 参数配置

### 1. YAML 是什么？

YAML 是一种常用于配置文件的数据格式。

ROS 可以使用 YAML 文件集中管理机器人参数。

### 2. 基本语法

- 使用空格缩进，不使用 Tab。
- 同一级内容需要对齐。
- 冒号后面需要有空格。
- 使用 `#` 添加注释。
- 可以使用列表和字典组织复杂数据。

### 3. PID 参数配置示例

```yaml
motor:
  max_speed: 10.0
  enable: true

pid:
  kp: 2.0
  ki: 0.1
  kd: 0.05
```

这种写法可以把控制器参数集中保存，避免把参数全部写死在代码中。

当需要调整 PID 参数时，可以修改配置文件，并通过相应机制重新加载参数。

需要注意：参数服务器中的值发生改变，不代表每个控制器都会自动重新读取参数。

## 八、控制组拓展学习

以下是根据本次课程布置的预习方向整理的基础知识。

### 1. TF 坐标变换

机器人系统通常存在多个坐标系，例如：

- 世界坐标系
- 机器人底盘坐标系
- 云台坐标系
- 相机坐标系

TF 用于管理坐标系之间的变换关系。

例如，相机识别到目标后，需要将目标在相机坐标系中的位置转换为云台或底盘坐标系中的位置，才能进一步计算控制指令。

### 2. PID 控制

PID 是常见的反馈控制算法，包含比例、积分和微分三个部分。

连续时间 PID 公式：

\[
u(t)=K_p e(t)+K_i\int_0^t e(\tau)d\tau+K_d\frac{de(t)}{dt}
\]

其中：

- P：根据当前误差产生控制作用。
- I：根据误差积累消除稳态偏差。
- D：根据误差变化趋势提供预测性调节。

在机器人控制中，还需要考虑输出限幅、积分饱和和微分噪声等问题。

### 3. 底盘运动学

对于差速底盘，左右车轮速度不同会使机器人产生转向运动。

假设：

- 左轮线速度为 \(v_L\)
- 右轮线速度为 \(v_R\)
- 两轮间距为 \(L\)

则车体前进速度：

\[
v=\frac{v_R+v_L}{2}
\]

车体角速度：

\[
\omega=\frac{v_R-v_L}{L}
\]

该公式适用于理想差速底盘模型。

通过底盘运动学，可以建立车轮速度与机器人整体运动之间的关系，为速度控制和运动规划提供基础。

## 九、学习总结


通过本次学习，我对 ROS 的整体架构有了初步认识。

以前接触 STM32 项目时，我通常把传感器读取、控制算法以及电机驱动放在同一个工程中实现。而 ROS 可以将这些功能拆分为不同节点，并通过统一的通信机制进行协作。

我认为本节课最重要的知识点是 ROS 的三种通信机制和 ros_control 的分层思想。

Topic、Service 和 Parameter 分别解决连续数据传输、请求应答和参数配置的问题；ros_control 则将上层控制算法与底层硬件通信分离。

后续需要重点学习 TF 坐标变换、控制器实现以及底盘运动学，并通过实际程序进一步理解这些概念。
