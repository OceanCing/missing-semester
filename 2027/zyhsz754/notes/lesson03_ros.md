# 第三课笔记：ROS架构与通信机制

## 一、 ROS 计算图架构
- **节点（Node）**：独立运行的程序单元。一个节点只负责一项具体功能（如读取雷达、控制电机）。
- **节点管理器（ROS Master）**：所有节点的“大管家”。负责节点的注册、发现，以及建立节点之间的连接。
- **功能包（Package）**：ROS软件的基本组织单元，包含节点源码、配置、启动文件等。

## 二、 ROS 四种通信机制
1. **话题（Topic）**：异步、单向通信（发布/订阅模型）。适合实时性、周期性的数据流（如传感器数据、速度指令）。接口格式为 `.msg` 文件。
2. **服务（Service）**：同步、双向通信（客户端/服务端）。适合短时、一次性的操作（如复位、查询状态）。接口格式为 `.srv` 文件。
3. **参数服务器（Parameter Server）**：全局共享字典。用于存储配置参数（如PID增益），供所有节点读写。
4. **动作库（Actionlib）**：基于话题和服务构建的高级通信机制。适合长时间运行的任务，支持过程反馈、任务取消等。

## 三、 常用命令行工具
- `rosnode list`：查看当前运行的所有节点。
- `rostopic list` / `rostopic echo`：查看话题列表 / 实时打印话题数据。
- `rosservice call`：调用特定的服务。
- `rosparam get` / `rosparam set`：读取/修改参数服务器中的参数。
