- shell脚本的变量相关

  ①STDOUT （标准输出）：就是正常的返回值（eg:敲 date，它吐出的时间，就是输出值）

# Git与Github

### 1.区分

- **Git**：是一个本地版本控制系统（用于记录每次提交的修改、比较差异、查看历史记录，并为新增功能创建独立的分支）
- **GitHub**：是一个基于 Git 的远程代码托管平台。用于团队协作，通过 PR（Pull Request）进行讨论、评审和合并团队认可的修改。

### 2.Git 核心工作流（三大区域）

代码从本地到云端需要经历三个步骤：
1. **`git add`**：将工作区修改过的文件添加到**暂存区**。
2. **`git commit`**：将暂存区的内容提交到**本地仓库**（仅记录在本地）。
3. **`git push`**：将本地仓库的提交推送到 **GitHub 远程仓库**。

### 3. 首次使用 Git 的配置
- **配置身份信息**（会写入提交记录）：
  `git config --global user.name "Your Name"`
  `git config --global user.email "you@example.com"`
- **SSH 认证**（免密登录，证明你有权访问远程仓库）：
  - 生成密钥：`ssh-keygen -t ed25519 -C "you@example.com"`
  - 查看公钥：`cat ~/.ssh/id_ed25519.pub`
  - 将公钥复制并添加到 GitHub 的 `Settings -> SSH and GPG keys` 中。

### 4. 常用基础命令
- `git clone <仓库地址>`：下载远程仓库及提交历史到本地。
- `git status`：查看当前分支和文件状态。
- `git diff`：查看尚未暂存的修改。
- `git log --oneline`：用简短格式查看提交历史。

### 5. 分支与团队协作规范
- **分支 (Branch)**：为开发新功能保留独立的开发线，避免影响主分支（main）的稳定。修改完成后再发起 PR 合并。

- **团队 PR 工作流**：
  1. 在 GitHub 网页上 **Fork** 团队仓库，复制一份到自己账号下。
  
  2. 本地 **Clone** 自己 Fork 的仓库。
  
  3. 创建 **Feature 分支** 进行开发（如 `git switch -c feature/hello`）。
  
  4. 完成修改后进行 **Add/Commit**，并 **Push** 到自己的远程仓库。
  
  5. 在 GitHub 网页上**发起 PR**，请求将你的分支合并到团队仓库。
  
  6. 等待 Review 评审，通过后由管理员 Merge 合并。
