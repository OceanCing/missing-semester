### 一、编译四步
 1. **预处理**：展开宏定义、处理预编译指令、删除注释，输出 `.i` 文件
 2. **编译**：把C/C++代码转为汇编指令，输出 `.s` 文件
 3. **汇编**：汇编代码转为二进制目标文件，输出 `.o` 文件
 4. **链接**：整合目标文件与库文件，生成最终可执行程序

 ### 二、静态库与动态库区别
 - **静态库(.a)**：链接时把库代码复制进程序，程序独立，体积大，库更新需要重编译。
 - **动态库(.so)**：链接仅记录引用，运行时系统才加载库到内存；体积小，库更新不用重编，多程序可共享。

 ### 三、Makefile、CMake、Catkin、ROS 的关系
 - **Makefile**：底层构建脚本，直接写编译规则；手写繁琐，跨平台差。
 - **CMake**：生成Makefile的工具，统一配置，跨平台编译。
 - **Catkin**：CMake的ROS专用扩展，专门管理ROS功能包、依赖、工作空间。
 - **ROS**：机器人框架，Catkin是它配套的构建系统。

 ### 四、CMake 指令关键区分+头文件路径关键字对比
 - **add_executable**：生成可执行程序
 - **add_library**：生成库文件，静态或动态库，供别人链接调用
 - **PRIVATE**：当前目标自己用，依赖它的其他目标看不到
 - **PUBLIC**：当前目标用，依赖它的目标也能继承
 - **INTERFACE**：不给当前目标用，只给依赖它的目标继承

### 五、推荐的外部构建流程

> 不在源码目录里直接生成中间文件，单独建 `build` 目录，方便清理。

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

### 六、变量与缓存

**6.1 普通变量与缓存变量**

- 普通变量：定义在 `CMakeLists.txt` ，作用域是当前目录及其子目录，每次运行 CMake 重新计算
- 缓存变量：保存在 `CMakeCache.txt` ，多次运行之间保留；修改默认值后需要删除缓存重新运行 CMake 才生效

 **6.2 修改 CMakeLists 为什么不生效**

 - CMake会缓存配置，旧参数保存在build目录，修改`CMakeLists.txt`后**直接make不会重新解析CMake**。
 - 解决：法一：删掉build文件夹重新构建；法二：执行`cmake ..`刷新缓存再编译。

 ### 七、package.xml 和 CMakeLists.txt
 - **package.xml**：ROS包的描述文件，声明包名、版本、依赖、作者信息，供catkin识别依赖。
 - **CMakeLists.txt**：编译配置文件，告诉catkin/CMake怎么编译源码、链接库、生成目标。

 ### 九、target_xxx 和 include_directories（更推荐target_xxx）
 - `include_directories`：全局生效，所有目标都会继承头文件路径，依赖混乱，容易冲突。
 - `target_include_directories`：作用于单个目标，搭配`PRIVATE/PUBLIC/INTERFACE`精细控制依赖传递，结构清晰、隔离性好。
 ### 十、Catkin工作空间目录划分、建包命令
 - **目录划分**
   - `src`：存放源码、功能包
   - `build`：cmake缓存、中间编译文件
   - `devel`：编译产物、环境配置脚本
   - `install`：安装输出
 - **创建包命令**
 `catkin_create_pkg 包名 依赖1 依赖2 ...`（包名在前，后面跟所有依赖包）

 ### 十一、大模型与本地执行的理解
 - 理解帮助：大模型只推理规划，没有本地权限；出错根源常在工具执行结果，不是模型本身。
 - 增强能力：本地命令执行、项目全文检索、联网查阅文档、操作人工审批、长上下文自动压缩、文件差分修改、沙箱隔离运行。
 ### 十二（思考补充）、步骤写太细导致上下文膨胀
 - 含义：如果给模型写很细碎、过于具体的操作指令，指令文本会变长，占用上下文额度；额度耗尽后，前面内容丢失，模型容易忘事、出错。
 - 做法：只给目标和约束，让模型自己规划步骤，精简提示词。
