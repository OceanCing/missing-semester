## 1. Linux 基础
### 1.1 Windows、MacOS、与Linux


三个系统都能运行程序、管理文件和联网，常用生态和使用方式不同。

区别：

|系统|常见的应用场景|特点|
| --- | --- | --- |
|Windows|个人桌面|软件、游戏生态丰富|
|MacOS|Apple生态|日常使用与开发|
|Linux（Ubuntu）|服务器、机器人、嵌入式|也可以作为桌面系统|


### 1.2 linux与发行版



Linux 通常指 **内核**。 Ubuntu、Debian等是“内核 + 系统工具 + 软件包 + 默认配置”组成的**发行版**。

DX团队使用Ubuntu的原因：与ROS的兼容性更好、部署环境的一致性和现有的开发生态。

### 1.3 机器人开发中的Linux



开发电脑通过网络连接机器人主机，控制程序在无桌面的环境运行

```text
开发电脑 --SSH/网络--> Ubuntu Server（机器人主机） ---> ROS节点/控制程序
```

>附：机器人主机上没有图形桌面，我们通常在电脑上写代码，然后通过SSH登录车上的主机，再启动程序。

### 1.4 Linux 的目录树从根目录 `/` 开始

```text
/
|—— home/user    用户文件
|—— etc          系统配置
|—— usr          程序与库
|——var          日志等可变数据
|—— dev          设备文件
```

其中 `user` 是示例用户名，实际使用时应该替换成自己的账户名。

#### 绝对路径与相对路径

| 写法 | 类型 | 含义 |
| --- | --- | --- |
| `/home/user/example` | 绝对路径 | 从根目录 `/` 开始 |
| `./hello.txt` | 相对路径 | 从当前目录开始 |
| `~/example` | 家目录路径 | 当前用户家目录下的 `example` |

几个特殊符号：

| 符号 | 含义 |
| --- | --- |
| `/` | 根目录，也是路径分隔符 |
| `~` | 当前用户的家目录 |
| `.` | 当前目录 |
| `..` | 上一级目录 |

Linux 路径 **区分大小写**。例如`README.md` 和 `readme.md` 是两个不同的文件名。

### 1.5 终端、Shell 与命令

注意：三者并不相同

路径：
```text
终端 Terminal  ->  Shell（Bash / Zsh）  ->  程序 / 系统
输入输出界面       解释命令、展开路径     ls查看文件、git管理版本
```

- **终端**：我们看到的输入输出窗口。
- **Shell**：解释命令的程序，常见的有 Bash 和 Zsh。
- **命令**：最终交给某个程序执行，例如 `ls`、`git`。

> 附：`cd` 这类命令通常由 Shell 自己执行，而 `ls`、`git` 会调用对应的程序。

## 2. Shell & Vim

### 2.1 Shell 命令的结构

格式：
```text
命令[选项][参数]
```

|`ls`|`-la`|`~/projects`|
| --- | --- | --- |
|命令|选项|参数|
|做什么|怎么执行，`-l` 显示详细信息，`-a` 包含隐藏项|操作哪个对象（这是哪个对象）|


### 2.2 查看位置与切换目录

| 命令 | 作用 |
| --- | --- |
| `pwd` | 显示当前目录 |
| `ls` | 列出目录内容 |
| `cd 目录` | 进入指定目录 |
| `cd ..` | 返回上一级 |
| `cd ~` | 返回家目录 |

附：输入目录时可以使用Tab补全


### 2.3 文件和目录操作

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `mkdir -p` | 创建目录，允许补齐父目录 | `mkdir -p ~/linux_demo` |
| `touch` | 创建空文件或更新时间 | `touch hello.txt` |
| `cp` | 复制文件 | `cp hello.txt hello-copy.txt` |
| `mv` | 移动文件或重命名 | `mv hello-copy.txt backup.txt` |
| `rm` | 删除文件 | `rm backup.txt` |
| `cat` | 直接查看文件内容 | `cat hello.txt` |
| `less` | 分页查看文件内容 | `less hello.txt` |

> 注意：`rm` 通常不会把文件放进回收站。删除前先用 `pwd` 和 `ls` 确认位置，记得只在练习目录里操作演示文件。


### 2.4 Shell 的四种常用组合

| 组合 | 例子 | 我的理解 |
| --- | --- | --- |
| 变量 | `name="RM"`、`echo "$name"` | 保存一个值，再用 `$name` 引用它 |
| 重定向 | `echo "hello" > hello.txt` | `>` 覆盖写入（原来的内容被覆盖），`>>` 追加到末尾 |
| 管道 | `ls -la \| grep txt` | 前一个命令的输出交给后一个程序 |
| 条件连接 | `mkdir -p demo && cd demo` | 前一条成功后才执行下一条|

>附：`&&` 会检查前一条命令是否成功。前一条失败，后面的命令就不会执行，所以 `mkdir -p demo && cd demo` 比直接连续执行两条命令更安全。

### 2.5 陌生命令的帮助窗口

| 方式 | 作用 |
| --- | --- |
| `ls --help` | 快速查看命令的选项和用法 |
| `man ls` | 打开完整手册，按 `q` 退出 |
| `Tab` | 补全命令或路径 |
| `↑` / `↓` | 调出历史命令 |

注：遇到陌生命令时，先看用途和参数，再在练习目录中尝试。

#### 注意点：

1. 命令和选项、参数之间要有空格，如：`ls -la`，不是 `ls-la`。
2. 变量赋值时等号两边不要空格：`name="RM"`，不是 `name = "RM"`。


#### 几个常见报错：

1. `command not found` ---> 命令拼写错误或者软件、程序未安装--->检查拼写、以及是否打了空格
2. `Permission denied` ---> 当前用户没有权限，或文件不可执行 ---> 检查是否在正确目录
3. `No such file or directory` ---> 路径或文件名不存在 ---> `pwd`、`ls`、路径大小写

## 3 Vim

### 3.1 Vim：在终端中编辑文件

Vim 常用于 SSH 和无桌面环境中的配置、代码编辑。它是一个**有模式的编辑器**，新手最容易卡住的地方不是命令太多，而是不知道自己现在处于哪个模式。

第一次打开 Vim 时，直接按键盘发现无法输入，这是因为启动后默认在**普通模式**。普通模式不是不能编辑，而是按键会被当成命令；要输入文字，先按 `i`。（应在英文输入法下按`i`，否则无效）

```text
启动 Vim--->普通模式（默认）
               |——— i ---> 插入模式（可以打字）
               |              |—— Esc ---> 普通模式
               |
               |———— : ---> 命令行模式（保存、退出、搜索）
                               |—— Enter ---> 执行命令
```

### 3.2 Vim 模式与必备按键

| 模式 | 怎么进入 | 用途 |
| --- | --- | --- |
| 普通模式 | 启动后默认进入，或按 `Esc` | 移动、删除、复制、粘贴 |
| 插入模式 | 普通模式按 `i` | 输入文本 |
| 命令行模式 | 普通模式按 `:` | 保存、退出、搜索 |

如果左下角看到 `-- INSERT --`，说明正在插入模式；此时按 `Esc` 就会回到普通模式。

常用按键：

| 按键 | 作用 |
| --- | --- |
| `h` `j` `k` `l` | 左、下、上、右移动 |
| `dd` | 删除当前行 |
| `yy` | 复制当前行 |
| `p` | 粘贴 |
| `u` | 撤销 |
| `/word` | 搜索 `word` |
| `n` / `N` | 跳到下一个 / 上一个匹配 |

| 命令 | 作用 |
| --- | --- |
| `:w` | 保存，但继续编辑 |
| `:q` | 没有修改，直接退出 |
| `:wq` | 保存并退出 |
| `:q!` | 放弃修改并退出 |

有未保存修改时，`:q` 会阻止退出；`:q!` 丢弃修改。

>注意：在终端 Vim 里，保存用 `:w`，不要用 `Ctrl+S` `Ctrl+S` ！！！！！

课堂演示练习：

1. `vim hello.txt` 打开文件。
2. 按 `i`，输入 `Hello, RM!`。
3. 按 `Esc`，输入 `:wq`，回车。
4. 再打开文件，按 `dd` 删除一行。
5. 按 `u` 撤销。
6. 输入 `/RM`，按回车，再按 `n` 找下一个匹配。
7. 按 `:q` 退出。

>附：先把 **Esc、i、:wq、dd、u、/word** 练熟，不要求一次背完所有快捷键。
>
> 卡住时先按 `Esc`，回到普通模式，再决定下一步。一定不要连续乱按。



## 4 Git 与 GitHub


### 4.1 Git 与 GitHub 的分工

| 工具 | 定位 | 主要作用 |
| --- | --- | --- |
| Git | 本地版本控制工具 | 记录提交、比较修改、查看历史、创建分支 |
| GitHub | 远程托管与协作平台 | 托管仓库、通过 PR 讨论评审、合并修改 |

>PR 是 **Pull Request** 的缩写，意思是请求团队评审并合并自己的修改。

>记忆方法：**Git 像游戏存档**。`add` 是挑选这一关要保存的内容，`commit` 是本地存档，`push` 是同步到公服，PR 让队友观战。

### 4.2 Git 的四个位置

```text
工作区 --git add--> 暂存区 --git commit--> 本地仓库 --git push--> GitHub
```

| 位置 | 作用 |
| --- | --- |
| 工作区 | 正在编辑的文件 |
| 暂存区 | 本次提交准备包含的内容清单 |
| 本地仓库 | 已经记录的提交历史 |
| GitHub 远程仓库 | 远程保存的提交历史 |

#### 补充：做一个只有本地的 Git 练习,用于熟悉git流程

```bash
mkdir -p ~/git_practice
cd ~/git_practice
git init
echo "hello" > hello.txt
git status
git diff
git add hello.txt
git diff --cached
git commit -m "Add hello"
git log --oneline
git status
```

>注：这里不用 GitHub，只用来观察文件怎么从工作区走到暂存区，再走到本地仓库，用于熟悉流程。
>    刚创建的新文件在 `git diff`里可能看不到内容，因为它是未跟踪文件；`git status` 会把它标成 untracked

### 4.3 首次使用git：提交作者

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

>这两项配置会写入提交记录，回答“这次修改由谁提交”。`--global` 对当前系统用户生效，但不等于登录 GitHub。

检查配置：

```bash
git config --get user.name
git config --get user.email
```

### 4.4 SSH 密钥：公钥与私钥

SSH 是“我有权限访问这个远程仓库”的证明。可以把它想成一把锁和一把钥匙：

- **公钥**像锁，可以交给 GitHub；
- **私钥**像钥匙，只能留在自己电脑上。

```bash
ssh-keygen -t ed25519 -C "you@example.com"
cat ~/.ssh/id_ed25519.pub
```

> 只能展示 `.pub` 公钥文件。私钥一旦泄露，别人就可能用它访问自己的 GitHub。

### 4.5 把 SSH 公钥添加到 GitHub

步骤： `Settings`--->`SSH and GPG keys`--->`New SSH
   key`--->选择`Authentication`--->填写名称，粘贴完整公钥

测试连接：

```bash
ssh -T git@github.com
```

>注：首次连接时要核对 GitHub 官方公布的主机指纹。

### 4.6 Git 常用命令：获取与查看

| 命令 | 我什么时候用 |
| --- | --- |
| `git clone <仓库地址>` | 把远程仓库下载到本地 |
| `git status` | 每次动手前、提交前，确认分支和改动 |
| `git diff` | 查看还没暂存的修改 |
| `git log --oneline` | 用简短格式看提交历史 |
>拓展| `git diff --cached` | 看已经暂存的修改 |
>    | `git remote -v` | 看本地仓库连接的是哪个远程地址 |

### 4.7 Git 常用命令：分支与提交

| 命令 | 作用 |
| --- | --- |
| `git switch -c feature/hello` | 创建并切换到功能分支 |
| `git add hello.txt` | 暂存指定文件 |
| `git commit -m "Add greeting"` | 记录一次本地提交 |
| `git push -u origin feature/hello` | 推送并建立跟踪关系 |
| `git switch main` | 切回主分支 |
| `git pull` | 获取并整合当前分支的远程更新 |

### 4.8 分支：为新功能保留独立开发线

`main` 保持稳定，`feature/hello` 承载本次修改，评审通过后再合并。


### 4.9 团队 PR 工作流

```text
Fork → Clone → Branch → Edit → Add → Commit → Push → PR → Review → Merge
```

| 动作 | 发生在哪里 | 结果 |
| --- | --- | --- |
| Fork | GitHub | 在自己的账号下复制出一个远程仓库 |
| Clone | 本地电脑 | 把远程仓库下载成本地副本 |
| Branch | 本地仓库 | 在同一个仓库里开一条开发线 |

## 5 总结

### 5.1 一次团队贡献的完整过程

```text
Linux     进入开发环境
Shell     定位与操作文件
Vim       编辑文件内容
Git       分支、暂存与提交
GitHub    PR、评审与合并
```
记住：**Git 记录版本，GitHub 支持协作。**

### 5.2 注意点

| 注意点 | 正确做法 |
| --- | --- |
| 把 `git add` 当成上传 | `add` 只是暂存，`commit` 才记录，`push` 才到远程 |
| 以为 `commit` 后队友能看到 | 还要 `push`，再PR |
| Fork 和 Branch 混为一谈 | Fork 是仓库副本，Branch 是仓库内的开发线 |
| 用 Windows 的习惯看 Linux 路径 | Linux 区分大小写，`README.md` 和 `readme.md` 不同 |
| 直接 `rm` 文件 | 先用 `pwd`、`ls` 确认，`rm` 通常不进回收站 |
| Vim 里连续乱按 | 先按 `Esc` 回普通模式 |
|一定不要把私钥发给别人 | 只提供公钥，私钥永远留在本机 |
