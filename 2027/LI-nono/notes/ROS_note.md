# ROS1系统学习笔记：
补充：进入docker：
    docker start ros1_env
    
## 1.ROS系统的概念：
    ROS系统不是windows/linux这样的操作系统，而是将一个个不同的程序联系起来的平台。
## 2.ROS系统中的三层架构：
    1.文件系统层（代码怎么组织）
        ROS强制要求将代码放在特定的“工作空间”，即catkin_ws。将代码打包成功能报（package）
    2.计算图层：
        将不同的独立程序连接起来，中间传递信息、、数据
    3.通信层（ai总结）：决定了进程间数据怎么物理连接（TCP/UDP）、怎么序列化、怎么排队。保障了跨机器（比如上位机与下        位机）通信的稳定性和可靠性。
## 2.ROS计算图中的三个核心概念：
    1.节点（Node）：一个节点就是上面说的一个独立运行的程序
    2.话题（Topic）：程序之间传递信息的单向通道(多对多），发布信息的叫做发布者（Publisher），接收信息的叫做订阅者（      Subscriber）
    3.ROS Master：相当于节点的登记处，不传输数据，只让节点与节点之间相互认识。
## 3.小海龟案例：
    1.打开三个终端：A、B、C
    2.进入docker容器+激活ROS环境：
        docker exec -it ros1_env /bin/bash（进入容器）
        source /opt/ros/noetic/setup.bash（激活环境）
    3.A终端：启动ROS Master
        roscore
    4.B终端：启动小海龟
        rosrun turtlesim turtlesim_node
    5.C终端：启动键盘控制
        rosrun turtlesim turtle_teleop_key
## 4.一次完整的通信过程(ai):
    1.启动Master：roscore 跑起来，监听11311端口，等大家来登记。
    2.发布者报到：比如小海龟键盘节点启动，它去Master那登记：“我是发布者，我要发 /cmd_vel 这个频道的广播，消息类型是      Twist。”
    3.订阅者报到：比如海龟节点启动，它去Master那登记：“我是订阅者，我要听 /cmd_vel 频道。”
    4.Master回地址：Master查了一下，哦，有个键盘节点在发这个频道，它住在 192.168.1.10:4567。于是Master把这个地址告       诉海龟节点（只此一次）。
    5.订阅者去连接：海龟节点拿到了地址，主动跑去连键盘节点，握手确认：“你要发的类型确实是 Twist，对上了！”
    6.直连传数据：从那以后，键盘节点发数据，直接通过底层的TCP管道塞给海龟节点。Master此时就下班了，后面的数据流它看      都看不见。
## 5.话题通信（topic)：
    1.发布者（talker)：
        在Master处报道：ros::init()
        建广播站：advertise<std_msgs::String>("/chatter", 10) 
                  在 /chatter 频道建个广播站，消息类型是String，消息队列深度是10
        发广播：在 while 循环里，造一个消息，填入数据，然后 pub.publish(msg) 发出去。发完就不管了，接着循环
    2.订阅者（listener）：
        报到：ros::init()
        订阅：subscribe("/chatter", 10, cb)接收/chatter频道并将消息交给cb这个函数来处理。
## 6.另一种通信：服务通信（Service）（ai总结）
    1.服务端（Server）：提供能力的人。比如小海龟里的 /spawn，它的功能是“凭空生成一只新海龟”。
    2.客户端（Client）：发起请求的人。
    规则：我打个电话（发请求），你接听，你回答（给响应）。在拿到结果之前，我卡在这里干等（同步阻塞）。如果电话没打     通（服务端没启动），客户端直接报错。

    什么时候用服务？ 比如切换机器人的模式（从“遥控模式”切到“自动驾驶模式”），或者让机器人“拍一张照”，你需要对方明确     告诉你“我切好了”或者“我拍完了”。
    不适用场景：高频数据流绝对不能服务，比如1秒钟100帧的雷达数据，用服务会直接把通信拖垮。
## 7.参数服务器（Parameter Server）
    1.参数服务器不在节点之间传数据流，它是全局共享的静态配置表
    2.特点：键值对（Key-Value）。谁都可以读，谁都可以改
    3.生命周期：它在 Master（roscore）里，roscore关閉 ，参数就没了
    4.注意：ROS1 里改参数，节点不会立刻收到通知（没有回调），通常是节点启动时读一次，或者手动触发读取
ps：私有参数vs全局参数
    一个只属于当前节点，一个大家都能访问
## 8.YAML 语法：配置表的“书写规矩”
    参数一多，全写在 launch 文件或代码里太丑了，因此要使用 .yaml 文件
    1.三大铁律：
        1.绝不能用 Tab 键缩进！ 只能用空格，通常是2个空格为一级。肉眼看不出来，机器一读就报错。
        2.冒号后面必须有空格！ 写 width: 640 是对的，写 width:640 会被当成一个普通字符串。
        3.大小写敏感。布尔值就是 true / false，不要写 yes / no，也不要写 True
