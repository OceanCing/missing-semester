## 一，Linux基础
**团队选择Ubuntu**：这是因为它的优良ROS兼容性，部署一致性和现有的开发生态。

## 三，Vim：在终端中编辑文件
Vim 是在 SSH 和无桌面环境中最常用的编辑器。它是一个“有模式”的编辑器，核心是三种模式的切换：
1. **普通模式**：默认模式，用于移动光标（`h j k l`）、删除（`dd`）、复制粘贴（`yy` / `p`）、撤销（`u`）。
2. **插入模式**：按 `i` 键进入，像普通记事本一样输入文字。
3. **命令行模式**：按 `Esc` 返回普通模式后，输入 `:` 进入。

### Vim 基本使用流程
1. `vim hello.txt` ：打开练习文件
2. `i` ：进入插入模式，输入文本
3. `Esc` ：返回普通模式
4. `:wq` ：保存并退出
5. `vim hello.txt` ：再次打开文件
6. `dd` `u` `/word` ：删除一行、撤销、搜索

  
## 四，Git与Github

### 1,分工
**Git：本地版本控制**
- 记录每次提交
- 比较修改、查看历史
- 为新功能创建分支

**GitHub：远程托管与协作**
- 托管 Git 仓库
- 通过 PR 讨论和评审
- 合并团队认可的修改

### 2,Git的四个位置
代码从本地到远程，需要经过四个区域：

**工作区** --(`git add`)--> **暂存区** --(`git commit`)--> **本地仓库** --(`git push`)--> **GitHub 远程仓库**

*   **工作区**：正在编辑的文件。
*   **暂存区**：本次提交的内容清单。
*   **本地仓库**：已记录的提交历史。
*   **GitHub 远程仓库**：远程保存的提交历史。

**【核心注意点】**
`Commit` 只是把修改记录到了**本地仓库**；
`push` 才真正把提交发送到**远程（GitHub）**！

### 3,SSH密钥：公钥与私钥

 
#### (1)**公钥与私钥的区别**
- **公钥**（以 `.pub` 结尾，如 `id_ed25519.pub`）：可以复制到 GitHub 的 SSH 设置中。
- **私钥**（如 `id_ed25519`）：不上传、不截图、不分享！ 

#### (2)**把 SSH 公钥添加到 GitHub的流程**

1. 打开 GitHub，进入 **`Settings`**。
2. 在左侧菜单找到 **`SSH and GPG keys`**。
3. 点击 **`New SSH key`**。
4. 选择 **`Authentication Key`**，填写一个名称（Title），并**粘贴完整的公钥**，点击保存。

配置完成后，可以在终端输入以下命令测试是否连接成功：
> ` ssh -T git@github.com `

### 4,Git 常用命令速查

#### (1). 获取与查看（状态与历史）
- `git clone <仓库地址>`：下载仓库及提交历史。
- `git status`：查看当前分支和文件状态。
- `git diff`：查看尚未暂存的修改。
- `git log --oneline`：用简短格式查看提交历史。

#### (2). 分支与提交（操作与流转）
- `git switch -c feature/hello`：创建并切换到功能分支。
- `git add hello.txt`：暂存指定文件。
- `git commit -m "Add greeting"`：记录一次本地提交。
- `git push -u origin feature/hello`：推送并建立跟踪关系。
- `git switch main`：切回主分支。
- `git pull`：获取并整合当前分支的远程更新。

### 5,团队 PR 工作流

默认使用 **Fork** 协作：远程复制仓库，本地开发，再向团队发起合并请求。
*(注：GitHub 的 Fork 是仓库副本，Branch 是仓库内的开发线)*

整个流程分为三个空间，具体步骤如下：

**1. GitHub（云端复制）**
- 团队仓库 >> **`Fork`** >> 个人 Fork

**2. 本地电脑（开发与提交）**
- 将个人 Fork **`Clone`** 到本地
- 创建并切换到 **`Feature` 分支**
- 修改代码 ➔ **`Add`** ➔ **`Commit`** 记录到本地
- **`Push`** 推送到个人的远程 Fork 仓库

**3. GitHub 协作（合并与评审）**
- 个人 Fork 接收提交 ➔ **`发起 PR`**
- 团队进行 **`Review`（评审）**
- 评审通过，**`Merge`（合并）** 到团队仓库
