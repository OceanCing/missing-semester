# 编译构建的底层逻辑
## 从源代码到可执行的四个阶段
计算机只认识二进制机器码，高级语言代码必须经过层层转换才能运行：
1.预处理：处理宏定义、头文件包含，生成.i 中间文件
2.编译：把预处理后的代码编译成汇编语言，生成.s汇编文件
3.汇编：把汇编语言转换成二进制目标文件（.o格式）
4.链接：整合所有目标文件和系统依赖库，生成最终的可执行程序
## 构建工具的演进
为什么会从 gcc 一路发展到 CMake？本质是项目规模变大后的必然升级：
- **gcc/g++ 手动编译**：只适合少量单文件，文件多了命令繁琐、依赖关系难管理
- **Makefile + make 工具**：相当于 “自动编译说明书”，提前定义好编译规则、顺序和依赖，敲一次 `make` 就能自动完成全量编译，实现了自动化。但项目体量变大、需要跨平台时，手写维护 Makefile 成本极高
- **CMake**：更高层的构建工具。你只需要写一份**平台无关**的 `CMakeLists.txt` 配置文件，CMake 就能自动生成对应平台的 Makefile（或 IDE 工程文件），完美解决大型项目、跨平台的构建难题
- [] 核心关系：**CMake 生成 Makefile，Makefile 指导 make 工具完成编译**
# Catkin 编译系统
- Catkin 是 ROS 在 CMake 基础上扩展的编译构建系统，是 ROS 开发的核心工具。
## Catkin 工作空间结构
- 工作空间就是开发 ROS 项目的根目录，标准结构包含 3 个文件夹：
- 目录	作用
- src/	存放所有功能包的源代码，是我们开发的主要操作目录
- build/	编译的中间文件、缓存，一般无需手动修改
- devel/	开发空间，存放编译生成的可执行文件、库文件、环境脚本
## 创建工作空间的完整步骤
### 1. 创建工作空间根目录和src目录
- mkdir catkin_ws
- cd catkin_ws
- mkdir src

### 2. 进入src，初始化工作空间
- cd src
- catkin_init_workspace

### 3. 返回工作空间根目录，执行编译
- cd ..
- catkin build
- [] 编译完成后，会自动生成 `build` 和 `devel` 两个目录。
