### 文件和目录操作

| 命令 | 作用 | 示例 |
|---|---|---|
| `mkdir -p` | 创建目录，允许补齐父目录 | `mkdir -p ~/linux_demo` |

| `cp` | 复制文件 | `cp hello.txt hello-copy.txt` |
| `mv` | 移动或重命名 | `mv hello-copy.txt backup.txt` |
| `rm` | 删除文件 | `rm backup.txt` |
| `cat` / `less` | 直接查看 / 分页查看 | `cat hello.txt` |

> **注意：** `rm` 通常不进回收站，删除前先确认路径和文件名

### Shell 的四种常用组合

| 组合 | 写法 | 说明 |
|---|---|---|
| 变量 | `name="RM"`<br>`echo "$name"` | 保存一个值，再通过变量引用它 |
| 重定向 | `echo "hello" > hello.txt` | `>` 覆盖写入，`>>` 追加到文件末尾 |
| 管道 | `ls -la \| grep txt` | 将输出交给下一个程序 |
| 条件连接 | `mkdir -p demo && cd demo` | 前一条成功后，再执行下一条 |

重定向举例：

- echo "第一行" > test.txt     # 文件内容：第一行
- echo "第二行" > test.txt     # 被覆盖，文件内容：第二行
- echo "第三行" >> test.txt    # 追加，文件内容：第二行、第三行
- cat test.txt

结果应该是：第二行，第三行

### 模式切换

```text

普通模式 ─────────→ 插入模式
```

## git 和 github

### Git 与 GitHub 的分工

> 多人修改同一项目，用版本记录和评审代替互相传压缩包。

| | Git | GitHub |
|---|---|---|
| 定位 | 本地版本控制 | 远程托管与协作 |
| 能做什么 | 记录每次提交<br>比较修改、查看历史<br>为新功能创建分支 | 托管 Git 仓库<br>通过 PR 讨论和评审<br>合并团队认可的修改 |
| 运行位置 | 你的电脑 | 网站（云端） |

### git的四个位置

> 先选择本次要记录的修改，再提交到本地，最后推送到远程。

```text
工作区 ──git add──→ 暂存区 ──git commit──→ 本地仓库 ──git push──→ GitHub 远程仓库
```

| 位置 | 说明 | 对应动作 |
|---|---|---|
| 工作区 | 正在编辑的文件 | 直接修改文件 |
| 暂存区 | 本次提交的内容清单 | `git add` |
| 本地仓库 | 已记录的提交历史 | `git commit` |
| GitHub 远程仓库 | 远程保存的提交历史 | `git push` |

> **重点：** `commit` 只记录到本地仓库；`push` 才把提交发送到远程。

**例（也是必需的提交过程）：**

- vim写笔记lesson1.md（工作区）
- git add 2027/123jpj194（进入暂存区)
- git commit -m "Add lesson 1 notes."（进入本地仓库）
- git push -u origin dev-123jpj194（进入github远程仓库）

*可以手动观察的命令：git status*

*该命令能指出文件当前在哪:*

- 红色 `未跟踪` / `尚未暂存`：在**工作区**
- 绿色 `要提交的变更`：在**暂存区***
- `Your branch is ahead of ...`：**本地仓库**有提交还没 push

### git常用命令：分支与提交

- `git switch -c feature/hello`：创建并切换到功能分支
- `git add hello.txt`：暂存指定文件
- `git commit -m "Add greeting"`：记录一次本地提交
- `git push -u origin feature/hello`：推送并建立跟踪关系（跟踪是将本地分支和某个远程分支绑在一起，建立跟踪后可直接进行git push/pull,git知道这个本地分支对应哪个分支）
- `git switch main`：切回主分支
- `git pull`：获取并整合当前分支的远程更新

> **习惯：** 切分支前先用 `git status` 查看当前状态

> 作业中我用 `git checkout -b dev-123jpj194` 创建分支，与 `git switch -c` 效果相同

## 团队pr工作流

- **Fork**：仓库副本
- **Branch**：仓库内的开发线

1. **Fork**：把团队仓库复制一份到个人账号
2. **Clone**：把个人 Fork 克隆到本地
3. **Feature 分支**：新建分支进行开发
4. **修改 / Add / Commit**：编辑文件，暂存并提交
5. **Push**：推送到个人 Fork
6. **发起 PR**：从个人 Fork 向团队仓库发起合并请求
7. **Review 评审**：团队成员检查并提出意见
8. **Merge**：评审通过后合并到团队仓库

> 有团队仓库推送权限时，可省略 Fork，使用同仓库分支协作

## 所以一次完整的团队贡献流程如下

1. 进入开发环境linux
2. shell定位和操作文件
3. vim编辑文件内容
4. git进行分支，暂存，提交
5. pr，评审，合并
