## 一、Linux 基础

### 三大操作系统对比

| 系统 | 定位 | 特点 |
| Windows 11 | 个人桌面 | 软件和游戏生态丰富 |
| macOS | Apple 生态 | 日常使用与开发兼顾 |
| Ubuntu (Linux) | 服务器/机器人/嵌入式 | 开源、可定制、也可作为桌面系统 |

##常见目录：
  - `/home/user`：用户文件
  - `/etc`：系统配置
  - `/usr`：程序与库
  - `/var`：日志等可变数据
  - `/dev`：设备文件
### 二、Shell 与 Vim
## 终端、Shell 与程序
- **Terminal（终端）**：输入输出的界面
- **Shell（Bash / Zsh）**：解释命令、展开路径、组织执行
- **程序 / 系统**：实际执行操作（如 `ls` 查看文件、`git` 管理版本）

### 常用命令

| 命令 | 作用 |
| `pwd` | 显示当前目录 |
| `ls` | 列出目录内容 |
| `cd 目录` | 进入指定目录 |
| `cd ..` | 返回上一级 |
| `cd ~` | 返回家目录 |
| `mkdir -p` | 创建目录（含父目录） |
| `touch` | 创建空文件/更新时间 |
| `cp` | 复制文件 |
| `mv` | 移动或重命名 |
| `rm` | 删除文件 |（通常不进回收站）
| `cat` / `less` | 直接查看/分页查看 |

### Shell 四种常用组合

1. **变量**：`name="RM"` → `echo "$name"` 保存并引用一个值
2. **重定向**：
 `>`：覆盖写入文件
 `>>`：追加到文件末尾
3. **管道**：`ls -la | grep txt` 将前一个命令的输出交给下一个命令
4. **条件连接**：`mkdir -p demo && cd demo` 前一条成功后再执行下一条

###陌生命令帮助入口
- `ls--help`：快速查看选项和用法
- `man ls`：打开手册（按 `q` 退出）
- `Tab`：补全命令或路径
- `↑ / ↓`：调出历史命令

### Vim 

#### 三种模式

| 模式 | 进入方式 | 功能 |
| 普通模式 | 启动后默认 / 按 `Esc` | 移动光标、删除、复制 |
| 插入模式 | 按 `i` | 输入文本 |
| 命令行模式 | 普通模式下按 `:` | 保存、退出 |

#### 普通模式常用按键

| 按键 | 操作 |
| `h` `j` `k` `l` | 左 / 下 / 上 / 右 |
| `dd` | 删除当前行 |
| `yy` / `p` | 复制当前行 / 粘贴 |
| `u` | 撤销 |
| `/word` | 搜索 word |

#### 保存与退出
- `:w`：保存
- `:q`：退出
- `:wq`：保存并退出
- `:q!`：放弃修改退出

## 三、Git 与 GitHub

### Git 的四个位置
工作区 → git add → 暂存区 → git commit → 本地仓库 → git push → GitHub 远程仓库

- 工作区：正在编辑的文件
- 暂存区：本次提交的内容清单（`git add`）
- 本地仓库：已记录的提交历史（`git commit`）
- 远程仓库：远程保存的提交历史（`git push`）

> commit 只记录到本地仓库；push 才把提交发送到远程。

### Git 常用命令

| 命令 | 作用 |
| `git clone <仓库地址>` | 下载仓库及提交历史 |
| `git status` | 查看当前分支和文件状态 |
| `git diff` | 查看尚未暂存的修改 |
| `git log --oneline` | 简短格式查看提交历史 |
| `git switch -c <branch>` | 创建并切换到新分支 |
| `git add <file>` | 暂存指定文件 |
| `git commit -m "message"` | 记录一次本地提交 |
| `git push -u origin <branch>` | 推送并建立跟踪关系 |
| `git switch main` | 切回主分支 |
| `git pull` | 获取并整合远程更新 |

### 团队 PR 工作流（Fork 协作）
团队仓库 → Fork → 个人 Fork → Clone → 本地电脑 → 创建 Feature 分支 → 修改 / Add / Commit → Push → 个人 Fork 接收 → 向团队仓库发起 PR → Review 评审 → Merge 到团队仓库

1. **Fork**：在 GitHub 上复制团队仓库到个人账号
2. **Clone**：下载自己的 Fork 到本地
3. **Branch**：创建功能分支进行开发
4. **Add → Commit → Push**：在本地记录修改并推送到远程
5. **Pull Request**：向团队仓库发起合并请求
6. **Review → Merge**：团队评审后合并入主仓库
