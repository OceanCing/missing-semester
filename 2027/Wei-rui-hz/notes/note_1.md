# Lesson 1 Notes: Linux, Vim & Shell, Git & GitHub


## 一、Linux 基础

### 1. Linux 与发行版

Linux 严格来说只是**内核**，我们平时说的"装 Linux"其实装的是发行版：
内核 + 系统工具 + 软件包 + 默认配置，打包成可以直接安装使用的系统。

常见的发行版有 Ubuntu、Debian、Fedora、Arch Linux。团队选择 Ubuntu，
主要因为 ROS 兼容性好、各台机器部署一致，开发生态成熟。

### 2. 机器人开发中的 Linux

在实际开发中，机器人主机跑的是 Ubuntu Server（无桌面），开发电脑通过
SSH 连上去写代码和部署。控制程序作为 ROS 节点运行，可以配置成开机
自动启动，不需要显示器。这也是为什么必须学会终端操作和 Vim。

### 3. 目录结构

Linux所有文件都在一颗“树”里，根是‘/’：
| 目录 | 存放内容|
|------|---------|
| `/home/user` | 用户文件 |
| `/etc` | 系统配置 |
| `/usr` | 程序与库 |
| `/var` | 日志等可变程序 |
| `/dev` | 设备文件 |

在安装Ubuntu的时候，因为驱动问题，我跟着ds敲了许多命令。其中有这样的
```bash
sudo mount /dev/分区名 /mnt   # 手动挂载一个分区到/mnt
sudo umount /mnt  #用完卸载
```

## 三、Vim

| 按键 | 操作 |
|------|------|
| `h j k l` | 左 / 下 / 上 / 右 |

### 2.插入模式
真正输入文字的模式，底部会显示-- INSERT --。

### 3.命令行模式

| 命令 | 作用 |

## 四、Git & GitHub

### 1. 分辨作用
Git 是本地版本控制；而GitHub 是远程托管与 PR 协作

### 2. Git 的四个位置

工作区 → 暂存区 → 本地仓库 → 远程仓库，对应的 add / commit / push

### 3. 首次配置

git config user.name / user.email；
SSH 密钥 ed25519 生成与添加：
```bash
ssh-keygen -t ed25519 -C "you@example.com"
#执行后直接回车即可，会自动生成两个文件：
#~/.ssh/id_ed25519    #私钥：不上传、不分享
#~/.ssh/id_ed25519.pub  #.pub结尾的是公钥：复制到GitHub

cat ~/.ssh/id_ed25519.pub   #查看公钥内容
ssh -T git@github.com  #验证连接
```
私钥不能分享：会导致最高权限泄露、服务器被攻击等严重后果。

### 4. 常用命令

#### 获取与查看

| 命令 | 作用 |
|------|------|
| `git clone <地址>` | 下载仓库及提交历史 |
| `git status` | 查看当前分支和文件状态 |
| `git diff` | 查看尚未暂存的修改 |
| `git log --oneline` | 简短格式查看提交历史 |
| `git pull` | 拉取并整合远程更新 |

#### 提交三板斧

```bash
git add hello.txt              # ① 暂存：把文件放进"本次提交清单"
git commit -m "Add greeting."  # ② 提交：记录到本地仓库
git push -u origin 分支名       # ③ 推送：发到 GitHub
```

#### 分支

| 命令 | 作用 |
|------|------|
| `git switch -c feature/xxx` | 创建并切换到新分支 |
| `git switch main` | 切回主分支 |
| `git branch` | 查看本地分支 |

#### 远程协作（Fork 工作流）

```bash
git remote -v                              # 查看远程仓库地址
git remote add upstream <原仓库地址>         # 添加上游
git fetch upstream                         # 抓取上游更新
git merge upstream/master                  # 合并上游更新到当前分支
```
### 6. Fork + PR 工作流

Fork → Clone → 分支 → 提交 → Push → PR → Review → Merge.
