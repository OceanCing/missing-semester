# 第一次培训笔记
## 本课学习目标：学习linux基础以及完成第一次PR
1. *各种操作系统*
> Windows、macOS与Linux
- 都能干运行程序、管理文件和联网的事，但之间使用方式不同，团队使用ubuntu：ROS兼容性、部署一致性和现有开发生态
2. *机器人开发中的Linux*
> 开发电脑通过网络连接机器人主机，控制程序可以在无桌面环境运行
- 开发电脑→ Ubuntu Server → ROS节点/控制程序
3. *Linux的目录从/开始*
> Linux 对路径大小写敏感
- /:根目录
- ~:家目录
- .:当前目录
- ..:上一级
4. *终端、Shell与命令*
> 在终端输入命令，由Shell解释，在交给程序运行
- Terminal终端 → Shell → 程序/系统
- 终端：输入输出界面
- shell：结束命令、展开路径、组织执行
- 系统/程序：ls查看文件，git管理版本
5. *Shell命令的结构*
- 命令（做什么）
- 选项（怎样执行）
- 参数（操作那个对象）
6. *当前位置与目录切换*
- pwd
- ls
- cd 
- cd ..
- cd ~
7.  *文件与目录操作*
- mkdir
- touch
- cp 
- mv
- rm
8. *Shell四种常用组合*
- 变量：保存一个值，在通过变量引用它
- 重定向：>覆盖写入；>>追加到文件末尾
- 管道：将输出交给下一个程序
- 条件连接&&：前一条成功后，再执行下一条
9. *陌生命令的帮助入口*
- ls --help：快速查看选项和用法
- man ls：打开手册，按Q退出
- Tab：补全
- ↑/↓：调出历史命令
10. *Vim：在终端中编辑文件*
> 一个有模式的编辑器
- 普通模式：移动、删除、复制
- 插入模式：输入文本
- 命令行：保存、退出
> 必备按键
- i：进入插入模式，开始输入文字
- h j k l；左/下/上/右
- dd：删除当前行
- yy/p：复制当前行/粘贴
- u：撤销
- /word：搜索word
11. *Git与GitHub的分工*
> 多人修改统一项目，用版本记录和评审代替互传压缩包
- Git：本地版本控制
- GitHub：远程托管与协作
12. *Git的四个位置*
- 工作区 → 暂存区 → 本地仓库 → GitHub远程仓库
**commit只记录到本地仓库；push才把提交发送到远程**
13. 首次使用Git：提交作者
> 姓名与油箱会写入提交记录
- 提交作者信息
- SSH认证
14. *SSH密钥*
- 公钥.pub
- 私钥**不能分享**
- 把SSH公钥添加到GitHub
15. *Git常用命令*
- 太多了看PPT吧
16. *分支：为新功能保留独立开发线*
> main保持稳定，feature/hello承载本次修改，评审后再合并
**分支让同一仓库中的开发互不打扰，提交点记录了每一步修改**
17. *团队PR工作流*
> 默认使用Fork协作
- 团队仓库 → 个人Fork → （本地电脑）clone → Feature分支 → 修改/Add/Commit → Push →（github协作）个人Fork接收提交 → 发起PR → Review评审 → Merge到团队仓库
18. *一次团队贡献的完整过程*
> Linux → Shell → Vim → Git → Github
- Linux：进入开发环境
- shell：定位与操作文件
- vim：编辑文件内容
- git：分支、暂存与提交
- GitHub：PR、评审与合并
**Git记录版本，GitHub支持协作**
