# ROS 架构与通信学习笔记

## 一、 认识 ROS

**ROS 是什么？**
ROS（Robot Operating System）是一个开源的元操作系统：它提供操作系统该提供的那些服务——硬件抽象、底层设备控制、常用功能的实现、进程间消息传递、软件包管理.

包含：
1. **通信中间件**：节点之间唯一的对话方式（话题、服务、参数）。
2. **工具链**：编译、启动、看、录，一样不少（catkin、rviz、rqt、rosbag）。
3. **软件生态**：几万个开源包，C++ 接口居多（OpenCV、PCL、Navigation 等）。

记住：**节点**（谁在干活） + **话题**（它们之间传什么）。

## 二、 为什么使用 ROS

   **为机器人量身定做**：发布/订阅、坐标变换、参数、录包……机器人要的东西，一开始就当成一等公民。
   **生态丰富，调试工具齐全**：遇到报错先搜一遍；算法包拿来改，比从零写快一个数量级。
   **代码可视化，便于团队分工**：rqt_graph 一眼看清谁连谁；接口谈好就能并行。
   **核心节点统一用 C++ 写 (roscpp)**：性能可控，且不用为调库再套一层。
   **可回放与可仿真**：rosbag 现场数据录下来回放；Gazebo 里先把逻辑跑通再上实车。

**方案：纯上位机**
视觉和控制逻辑全跑在上位机 miniPC 的 ROS 节点里。蓝色在「算」（闭环、状态机、参数），下位机只负责「送」（EtherCAT 到 CAN 帧的转换传输）。
   好处：控制代码修改便捷，不用烧固件；通信和计算解耦，逻辑越薄越不容易错。

## 三、 三层架构：把 ROS 放进脑子里的一张图

1. **文件系统层 (File System)**：解决「代码怎么组织」（工作空间 -> 功能包 -> 源码/配置）。
2. **计算图层 (Computation Graph)**：解决「程序怎么协作」（节点、话题、服务、参数、消息）。
3. **通信层 (Communication)**：解决「数据怎么走」（TCPROS/UDPROS，连接建立、序列化、队列、断线重连）。

### 计算图的五个零件
*   **节点**：一个独立跑着的进程，干一件小事。
*   **话题**：一条有名字的广播频道，发布者写、订阅者读。
*   **消息**：话题上传输的数据结构，`.msg` 定义字段。
*   **服务**：一问一答的远程调用，有请求也有应答。
*   **参数**：全局共享的配置表，key-value。

## 四、 核心：ROS Master 与通信流程

数据根本不经过 Master！

**Master 到底管什么？**
1. 名字注册（谁发布了什么、谁提供了什么服务）
2. 名字查询（按名字把双方介绍给对方）
3. 参数服务器（全局参数的存放地）
4. 状态监控（谁还活着、谁掉线了）

**一次话题通信的 6 个步骤：**
1. **启动 Master**（`roscore` 起在 11311 端口）。
2. **发布者报到**（向 Master 注册）。
3. **订阅者报到**（向 Master 注册）。
4. **Master 回地址**（把发布者的 IP 和端口告诉订阅者，只此一次）。
5. **订阅者去连接**（订阅者主动连发布者，握手确认消息类型一致）。
6. **直连传数据**（之后走这条 TCP 连接，Master 不再出现）。

 注意：Master 挂了，已连上的照跑；新来的连不上。

## 五、 文件系统层：工作空间与 ROS 包

### 工作空间结构 (catkin_ws)
*   `src/`：存放代码（进版本库）。
*   `build/`：编译中间文件（可删，别进 git）。
*   `devel/`：编译产物（`setup.bash`、可执行文件）。
*   **排雷**：每开一个新终端都要 `source devel/setup.bash`，或者写进 `~/.bashrc` 一劳永逸。包名必须全局唯一。

### 一个 ROS 包里到底有什么？
八样东西，放错地方编译就过不了：
*   `CMakeLists.txt`：编译规则（编什么、链什么）。
*   `package.xml`：名片（名字、版本、依赖）。
*   `include/`：对外暴露的头文件 `.h`/`.hpp`。
*   `src/`：C++ 源文件 `.cpp`。
*   `scripts/`：可执行脚本。
*   `msg/` / `srv/`：自定义消息/服务（配合 CMakeLists 编译）。
*   `launch/`：启动文件 `.launch`（一次拉起多个节点）。
*   `config/`：参数文件 `.yaml`。
*   **注意**：服务目录在 ROS 里叫 `srv`，别建成 `service/`。

## 六、 三大通信

### 1. 话题 (Topic)：发布 / 订阅
*   **类比**：广播电台。发布者只管往频道里喊，订阅者爱听不听。
*   **特点**：异步（发完就返回）、多对多、有队列（`queue_size` 缓冲深度）、断线自动重连。
*   **典型场景**：传感器数据、控制指令（连续变化的数据流）。
*   **API**：`advertise()` 创建发布者，`publish()` 发消息，`subscribe()` 创建订阅者。回调跑在 spin 线程里，别做耗时操作。

### 2. 服务 (Service)：请求 / 应答
*   **类比**：打一次电话。你问一句，他答一句，答完就挂。
*   **特点**：同步阻塞（代码停在那等结果）、一对一。
*   **典型场景**：切换模式、取一次地图（需要一个明确结果）。
*   **约定**：`.srv` 文件上下两段用 `---` 隔开（上面请求、下面应答）。

### 3. 参数 (Parameter)：全局配置墙
*   **类比**：贴在墙上的配置表。谁都能看，改一次所有人都看到。
*   **特点**：全局 key-value（存在 Master 里）、以静态配置为主（启动时读一次）、改参数不用重启节点。
*   **典型场景**：阈值、相机内参、PID 参数。

## 七、 配置文件 YAML

参数一多，就该写进 YAML 文件批量灌入。

**语法规矩（极易报错）：**
1. **只用空格缩进，绝不用 Tab**（两个空格算一级）。
2. **冒号后面必须有空格**（`key: value` 对，`key:value` 错）。
3. **大小写敏感**（布尔值用 `true`/`false`，不要写 `yes`/`no`）。
4. `#` 是注释。

**三种结构：**
*   **标量**：`speed: 1.5`、`name: "sentry"`、`debug: true`。
*   **列表**：`ports: [8080, 8081]`。
*   **字典**：`camera: { width: 640, height: 480 }`。
