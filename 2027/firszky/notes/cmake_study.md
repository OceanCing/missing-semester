## 一、 编译工具的发展与 CMake 简介
随着源代码文件的增加，直接用 `gcc/g++` 命令编译效率低下，于是出现了 `Makefile`。但随着工程体量进一步增大，Makefile 难以满足需求，且无法灵活跨平台。
而CMake是一个跨平台的编译工具，是一个更高层次的构建工具。
   **核心作用**：CMake 通过编写简单的配置文件（CMakeLists.txt），去生成本地的 Makefile，最后调用 make 工具进行编译。
   **优势**：配置文件独立于运行平台和编译器，实现了良好的跨平台性。

## 二、 C++ 源代码到可执行程序的过程
计算机只能执行二进制代码，编译器负责将高级语言翻译成机器语言。具体分为四个步骤：
1.  **预处理**：处理宏定义、头文件包含等。
2.  **编译**：将预处理后的代码翻译成汇编语言。
3.  **汇编**：将汇编代码转换为机器指令（目标文件）。
4.  **链接**：将多个目标文件及库文件链接在一起，生成最终的可执行文件。

### 1. 预处理阶段 (Preprocessing)
*   **执行程序**：预处理器（`cpp`）。
*   **输入/输出**：文本文件 `.c` -> 修改后的文本文件 `.i`。
*   **主要工作**：
    *   删除所有的 `#define` 并展开宏定义。
    *   处理所有的条件预编译指令（如 `#if`、`#ifdef`）。
    *   处理 `#include` 指令，将被包含的文件插入到该指令的位置。
    *   删除所有的注释。
    *   添加行号和文件标识，以便编译时产生调试用的行号。

### 2. 编译阶段 (Compilation)
*   **执行程序**：编译器（`ccl`）。
*   **输入/输出**：文本文件 `.i` -> 汇编语言程序 `.s`。
*   **主要工作**：对预处理后的代码进行词法分析、语法分析、语义分析及优化，最终生成汇编语言代码。

### 3. 汇编阶段 (Assembly)
*   **执行程序**：汇编器（`as`）。
*   **输入/输出**：汇编语言程序 `.s` -> 可重定位目标程序 `.o`（二进制）。
*   **主要工作**：将汇编指令逐条翻译成机器指令，打包成一种叫**可重定位目标文件**（Relocatable Object File）的格式，保存在 `.o` 文件中。

### 4. 链接阶段 (Linking)
*   **执行程序**：链接器（`ld`）。
*   **主要工作**：目标文件 `.o` 中往往引用了其他库（如 `printf` 函数存在于 `printf.o` 中）。链接器负责将各个目标文件、库文件合并，生成最终的可执行目标文件。
*   **链接的两种方式**：
    *   **静态链接**：将所需库的代码直接复制并嵌入到可执行文件中（生成文件大，浪费空间，更新麻烦）。
    *   **动态链接**：在程序加载或运行时，由动态链接器加载共享库（`.so` 文件），在内存中进行链接。

### 5. ELF 目标文件格式 (以 Linux 为例)
目标文件（`.o`）和可执行文件都采用 ELF (Executable and Linkable Format) 格式，主要包含以下节（Section）：
*   `.text`：已编译程序的机器代码。
*   `.rodata`：只读数据（如 `printf` 语句中的格式串）。
*   `.data`：已初始化的全局和静态 C 变量。
*   `.bss`：未初始化的全局和静态 C 变量（运行时在内存中分配并初始化为 0）。
*   `.symtab`：符号表，存放程序中定义和引用的函数和全局变量信息。
*   `.debug` / `.line`：调试符号表，保存变量信息和源代码行号映射。

## 二、 CMake 基础与核心语法
*   **CMake 概念**：一个跨平台的自动化构建系统，使用 `CMakeLists.txt` 配置文件来生成标准的构建文件（如 Makefile）。
*   **核心语法**：
    *   `cmake_minimum_required(VERSION 3.10)`：指定最低 CMake 版本。
    *   `project(MyProject)`：定义项目名称。
    *   `add_executable(hello main.cpp)`：将源文件编译成名为 `hello` 的可执行文件。

###  CMake 高级特性

*   **自定义 CMake 模块和脚本** ：将复用的逻辑封装为 `.cmake` 文件，通过 `include()` 加载。模块内函数建议加前缀防冲突。
*   **构建配置和目标** ：区分**多配置生成器** （如 VS,构建时通过` --config Release` 切换）和**单配置生成器**（如Unix Makefile，需指定 `-DCMAKE_BUILD_TYPE=Release`）。项目可定义多个构建目标。
*   **高级查找和配置** ：`find_package` 可通过 `COMPONENTS` 按需查找子模块；使用 `configure_file()` 将 CMake 变量注入到代码文件中。
*   **生成自定义构建步骤** ：`add_custom_command()` 基于依赖驱动生成文件（输出不存在或依赖更新时才执行）；`add_custom_target()` 定义一个不产生输出文件的构建目标，通常用于将多个自定义命令组织在一起(除非使用 ALL 关键字，否则自定义目标不会在默认构建中执行，需要显式指定目标名)
*   **跨平台和交叉编译* *：使用 **`Toolchain File` (工具链文件)** 指定交叉编译环境（必须在首次 cmake 时指定）。
*   **目标属性和配置** ：使用 `set_target_properties()` 精细控制；推荐使用 `target_xxx` 系列指令,因为它们支持 PUBLIC/PRIVATE/INTERFACE 可见性控制，依赖关系更明确。

## 三、 Catkin 编译系统
ROS对CMake进行了扩展。

### 1. Catkin 工作空间结构
一个标准的 catkin 工作空间通常包含以下三个主要目录：
*   `src`：存放 package 源代码包的目录。
*   `build`：存放 cmake 和 catkin 的缓存和中间文件（通常不需要关注）。
*   `devel`：开发空间，存放开发过程中生成的可执行文件和库。

### 2. 功能包 (Package) 结构
在 `src` 目录下创建包，通常包含以下关键文件：
*   `CMakeLists.txt`：包的编译规则（必须）。
*   `package.xml`：包的描述信息（必须）。
*   `src/`：存放 C++ 源代码。
*   `include/`：存放 C++ 头文件。
*   `scripts/`：存放可执行的 Python 脚本等。
*   `msg/`:存放自定义消息。
*   `srv/`:存放自定义服务。
*   `models/`:存放3D模型文件。
*   `urdf/`:存放urdf文件。
*   `launch/`:存放launch文件。

## 四、 大模型与 Agent 基础概念
*   **LLM (大语言模型)**：基于大量参数的人工智能模型，其推理过程是对输入字符串进行概率分布采样，具有固定的上下文窗口。
*   **Agent (智能体) 软件**：让大模型能够使用工具、与外部环境交互（如读写本地文件），并持续执行任务的系统。
*   **AGENTS.md**：类似于项目给人类看的 README，它是给 AI 编程 Agent 看的项目说明书，用于提供背景和规范。
*   **Skill (技能)**：一组可复用的任务指令和配套资源，用于指导 Agent 完成特定类型的任务。

### 构建 AI 编程 Agent 

#### 1. THE Mental Modal
Agent 的运行：
1. **用户**
2. **LLM** 决定需要使用工具，并返回结构化的工具调用请求。
3. **本地程序**接收请求，在本地执行对应的工具。
4. **执行结果**被送回给 LLM。
5. **LLM** 结合上下文和结果，继续决策或给出最终回复。
*核心原则：LLM 绝不直接触碰本地文件系统，它只负责发出指令，本地代码负责执行。*

#### 2. Agent 必备的三个基础工具
要让 Agent 能写代码，必须实现以下三个本地函数：
*   **读取文件 (Read File)**：以便 LLM 能够查看您的代码。
*   **列出文件 (List Files)**：以便其能够浏览您的项目。
*   **编辑文件 (Edit File)**：以便其提供创建和修改代码的指令，处理两个案例：
    *  1. 当 `old_str` 为空时：创建新文件（或覆盖）。
    *  2. 当 `old_str` 不为空时：在文件中查找 `old_str` 并替换为 `new_str`。

#### 4. 解析与执行
*   **解析器**：程序读取 LLM 的回复，寻找以 `tool:` 开头的行，提取出工具名和 JSON 参数。
*   **API包装**：把所有事情都整合起来一起发送给大模型。

#### 5. Agent 主循环 (The Agent Loop)
双层循环架构：
*   **外层循环**：等待用户输入，并将用户消息加入对话历史。
*   **内层循环**：呼叫LLM,检查工具调用。
    *   **如果没有调用工具**：请打印响应并断开内循环。
    *   **如果有工具调用**：如果需要工具,请执行,将结果添加到对话中,再次循环。
