### 第1步：克隆拉取

#### git clone 地址后面的.git含义

网址末尾的 `.git` 是远程仓库的路径，告诉 Git 去下载仓库数据，而不是打开 GitHub 上的网页。

```text
https://github.com/lichen/missing-semester.git
       网站        用户名    仓库名      仓库数据
```

GitHub 上一个人能看的页面是 `https://github.com/lichen/missing-semester`。仓库真正给 `git clone` 用的地址，按 Git 的习惯在仓库名后面加 `.git`。服务器上存放仓库数据的目录就习惯叫 `仓库名.git`，所以克隆地址写成这样。

克隆之后，你电脑上的目录名是 `missing-semester`。Git 会把网址最后一截拿来当目录名，并去掉末尾的 `.git`。里面那个隐藏的 `.git` 目录是另一回事：它是克隆时在本地新建的，用来存放提交记录、分支和远程地址，不是从网址上把一个叫 `.git` 的文件下载下来。

在 GitHub 上，不写这四个字符也可以克隆，`https://github.com/lichen/missing-semester` 同样能用。写上 `.git` 只是把“要仓库数据”说完整。

### git 其他机制

#### q:我在不同目录中使用git命令都没关系？是每个目录都有.git吗？我在不同目录下使用git switch 都没问题？

整个仓库只有一处 `.git`，在克隆出来的 `missing-semester` 这一层。`2027`、`2019` 这些子目录里没有各自的 `.git`。

你在仓库内部的哪个目录运行 Git，Git 都会从当前目录往上找，找到这唯一的 `.git` 后，命令就作用在整个仓库上。所以在 `2027` 里执行 `git switch`，和在 `missing-semester` 根目录里执行，切换的是同一套分支。切换会改动整个仓库里的文件，不只是你当前站着的那个文件夹。

离开这个仓库之后就不再是同一处。比如回到 `~/DX_test`，那里没有 `.git`，Git 会报不是一个仓库。如果进入另一个带有自己 `.git` 的项目，命令就作用在那个项目上。

有一个位置上的差别：切换后如果新分支里没有你当前所在的目录，分支可以切过去，但终端还停在一个已经不存在的路径里。这时先 `cd` 回仓库根目录即可。

## shell

### 作业用到的命令

脚本内容：

```bash
#!/bin/bash
cd "$(dirname "$0")"

{
  date
  history -r "$HOME/.bash_history"
  history 10
  wc -m ../notes/lesson1.md
} > output.txt
```

**`#!/bin/bash`**  
这行写在文件第一行。直接运行这个文件时，系统用 Bash 来执行它。`history` 是 Bash 自己的命令，所以要指定 Bash。

**`cd "$(dirname "$0")"`**  
`$0` 是用来启动脚本的路径，例如 `2027/lichen/homework/collect.sh`。`dirname` 去掉文件名，剩下 `2027/lichen/homework`。`cd` 走进这个目录。

之前：脚本里的相对路径跟着你终端当时所在的目录走。在仓库根目录运行，`../notes/lesson1.md` 会找错地方。  
之后：相对路径固定跟着脚本所在的 `homework` 目录走。在哪个目录启动脚本，结果一样。

**`date`**  
把当前系统时间写成一行，送到标准输出。磁盘上的文件没有变化。

**`history -r "$HOME/.bash_history"`**  
终端里敲过的命令记在你用户目录的 `.bash_history` 文件里。脚本启动时会另开一个 Bash，这个新 Bash 的命令列表是空的，所以脚本里直接写 `history` 什么都打不出来。

`-r` 是把那个文件读进这个新 Bash 的命令列表。`.bash_history` 文件本身不被修改。

**`history 10`**  
从刚读入的列表里取出最后 10 条，写到标准输出。还停在终端里、尚未写入 `.bash_history` 的命令不会出现。想让它们也进去，先在终端执行一次 `history -a`，再运行脚本。

**`wc -m ../notes/lesson1.md`**  
从 `homework` 往上一级，进入 `notes`，数 `lesson1.md` 的字符数。空格和换行也算。输出形如 `328 ../notes/lesson1.md`。`wc -w` 数的是英文单词，中文笔记会差得很远，这里用 `-m`。

花括号把三条命令收成一组，这一组共用末尾的一个 `>`。运行前，`output.txt` 不存在，或者还是上次的内容。Shell 看到 `>` 后会新建这个文件；文件已存在就先清空。这三条命令写向标准输出的字，都进入该文件。终端上不再出现这三样结果。

脚本写好后先给它执行权限：

```bash
chmod +x 2027/lichen/homework/collect.sh
```

之前：文件只是一段文字，直接运行会被拒绝。  
之后：文件内容不变，但系统允许把它当作程序执行。

### 其他知识

```
demo() { echo "stdout: hello"; echo "stderr: oops" >&2; }
```

`demo` 是你在当前终端里临时起的一个名字，不是系统里现成的程序，也不是一个文件。那一行本身不产生任何文件，只是把后面要反复用的两步记下来。

#### 终端里一次操作的最小单位

一次操作就是你输入的**一行**，以回车结束。Shell 先把这一行拆开，再按拆开的结果做事。它拆出来的东西只有这几类：

| 片段   | 例子                 | Shell 拿它做什么                   |
| ------ | -------------------- | ---------------------------------- |
| 命令名 | `echo`、`demo`       | 决定要运行谁                       |
| 参数   | `"stdout: hello"`    | 原样交给那个命令                   |
| `;`    | 两个 `echo` 中间那个 | 这一行里上一条命令结束，下一条开始 |
| 重定向 | `> out.txt`、`>&2`   | Shell 自己处理，命令看不到这段文字 |

命令真正跑起来时，手里已经有三条通道，编号是固定的：

- `0`：标准输入，命令从这里读
- `1`：标准输出，正常结果从这里写
- `2`：标准错误，错误信息从这里写

什么都不写时，这三条都连着终端。所以命令写到 `1` 或 `2` 的字会直接出现在屏幕上，从 `0` 读就是在等你键盘输入。

#### 第一个命令每个词是什么

```bash
demo() { echo "stdout: hello"; echo "stderr: oops" >&2; }
```

按从左到右的顺序：

1. `demo`：要记住的名字。
2. `()`：声明“这是一个函数”。括号是空的，因为这里不接收参数。
3. `{`：函数内容开始。
4. `echo "stdout: hello"`：第一条要执行的命令。
5. `;`：第一条结束。
6. `echo "stderr: oops" >&2`：第二条命令。
7. `;`：第二条结束。花括号前要有这个分号。
8. `}`：函数内容结束。

回车之后，终端只是记下：以后输入 `demo`，就按顺序做花括号里的两条。这一行没有输出，也没有新建文件。

#### `echo` 做什么

`echo` 是一条命令，功能只有一件：把你在它后面写的参数，写到自己的标准输出，最后再补一个换行。

```bash
echo "stdout: hello"
```

这里的结构是：命令名 `echo`，一个参数 `"stdout: hello"`。引号让里面的空格留在同一个参数里。这行字就写在命令里，不是从某个文件读出来的。它写到通道 `1`。通道 `1` 还连着终端时，屏幕上就出现：

```text
stdout: hello
```

函数里的第二条：

```bash
echo "stderr: oops" >&2
```

`echo` 仍然把参数写到自己的通道 `1`。紧跟的 `>&2` 是 Shell 在启动这个 `echo` 之前做的：把这个 `echo` 的通道 `1` 接到通道 `2` 现在指向的地方。所以这行字走的是标准错误。两条命令因此各走一路，后面才能分别演示 `>` 和 `2>`。

#### 文件是哪一步产生的

`demo > out.txt` 里的 `out.txt` 事先不用创建。你按下回车后，顺序是：

1. Shell 看到 `> out.txt`，自己去打开这个名字。文件不存在就新建一个空文件；已经存在就把内容清空。
2. Shell 把 `demo` 的通道 `1` 接到这个文件，通道 `2` 仍留在终端。
3. Shell 才开始执行 `demo` 记住的那两条命令。
4. 第一个 `echo` 往通道 `1` 写，字进入 `out.txt`。第二个 `echo` 往通道 `2` 写，字仍出现在终端。
5. 两条都结束后，Shell 关掉文件。`out.txt` 里留下 `stdout: hello`。

写文件的是 Shell 的重定向，`echo` 只知道自己往通道 `1` 写了一行字，它并不知道有个叫 `out.txt` 的文件。

从文件读入才要求文件先存在。`cat < out.txt` 里的 `<` 是让 Shell 打开已有文件，接到命令的通道 `0`。这个文件能被打开，是因为前面的 `demo > out.txt` 已经把它产生出来了。

**Bash 是一种 shell**

。shell 是读入一行命令并执行的程序，Bash 是其中常用的一种。脚本第一行 `#!/bin/bash` 指定用 Bash 来执行这个文件。

`shuange.sh` 里写的就是 shell 命令和 shell 语法。`cd`、`history`、`{ }`、`$0`、`>` 由 Bash 自己处理。`date`、`dirname`、`wc` 是 Bash 再去启动的程序，它们的输出仍然交给 shell 的重定向。

`.sh` 只写在文件名里，用来标明这是一份 shell 脚本。系统不看这个后缀。真正决定用 Bash 执行的是第一行 `#!/bin/bash`，再加上执行权限。文件改名为 `shuange` 后，用同样的方式运行，效果不变。
