# 10 工程排查与类别映射

使用同一份自训模型包，对数字 7 运行正常、漏归一化、反色和错误类别表四个受控案例。

## 实验记录

窗口中 normal 的标签为 **7**，wrong-label-map 变为 **3**。核对保存结果：

| 案例 | class_id | label | score |
| --- | --- | --- | --- |
| normal | 7 | 7 | 1.0 |
| raw | 7 | 7 | 1.0 |
| invert | 10 | negative | 约 0.999981 |
| wrong-label-map | 7 | 3 | 1.0 |

错误类别表案例的 ID 和分数都没有变化，只是将 ID 7 解释成字符串 3。应修复 ID→标签映射，无须重训。倒序仅作用于该案例，原模型包没有被改写。

`model_hash_matches=true`，ONNX 文件与 metadata 中登记的 SHA256 一致。文件和 logits 对齐仍需配合正确的预处理、类别表与接受规则，才能解释最终结果。

## 排查顺序

| 证据 | 检查方向 |
| --- | --- |
| 两端实际张量不同 | 裁剪、通道、尺寸、归一化和布局 |
| 输入相同，但模型或类别表不同 | 文件来源、hash、类别顺序 |
| 同输入同权重，logits 差异显著 | 导出算子、运行库和精度设置 |
| 两端数值一致，但都识别错误 | 标注、数据来源、错例和模型评价 |
| 离线正确，ROS 异常 | 实际帧、时间戳、队列和状态更新 |

本轮已经走通 CPU 训练与数据检查 → 验证与错例 → ONNX → Python/C++ 对齐 → 视频 ROI、分类和 PnP → ROS 结果订阅。

阅读真实工程时，沿启动入口、图像输入、候选与 ROI、模型、解算与坐标系、跟踪、结果发布依次查找。DynamicX 的具体实现需要按实际仓库、分支和提交核对；这里的教学 CNN 不代表战队当前方案。
