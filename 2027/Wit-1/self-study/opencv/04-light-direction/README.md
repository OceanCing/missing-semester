# OpenCV 04：灯条方向筛选

上一课取最小外接矩形的长边除以短边，因此横放的细长红条也会通过面积与长短边比条件。本课保持这两个条件不变，加入长轴相对竖直方向的夹角，单独观察方向条件的作用。

## 实验记录

将角度上限从 15° 调到 30°，观察到左右各倾斜约 25° 的两根红条出现绿框，`Direction passed` 从 1 变成 3。原本的竖直条继续保留，约 60° 的两根斜条和横放条仍被排除。运行日志中 `Shape candidates` 始终为 6，说明改变的是方向筛选结果，面积和长短边比筛选结果没有变化。

教学图像经过像素化后，25° 红条的实际测量值约为 25.0169°。窗口标签只显示一位小数，因此标签为 25.0，但角度上限严格设为 25° 时仍会被排除，调到 26° 后通过。筛选使用未四舍五入的数值。

左倾 25° 与右倾 25° 的两根条不平行，虽然本课都显示为 25°。只比较这个角度大小是否相等不足以判断两根的相对方向；[下一课](../05-light-pairing/README.md)保留长轴方向并比较两根之间的夹角。

## 本课如何定义方向

图像坐标中 x 向右、y 向下。这里定义无方向的长轴与竖直线之间的锐角：

| 姿态 | 本课的倾斜角度 |
| --- | --- |
| 竖直 | 0° |
| 向左或向右倾斜 25° | 都记为 25° |
| 横放 | 90° |

这是本课明确约定的角度，并非直接照搬 `cv::RotatedRect::angle` 的值。[light_direction.hpp](src/light_direction.hpp) 从矩形相邻顶点形成的边中选取长边，计算它与竖直方向的夹角。长边朝上或朝下不影响结果，本课也不区分左倾和右倾；后续比较两根灯条是否平行时还需要保留方向信息。

筛选条件为：

```text
HSV 满足红色范围
并且轮廓面积 >= 200
并且长短边比 >= 3.0
并且倾斜角度 <= Max tilt deg
```

固定角度上限是教学中的几何规则，实际设置需要结合目标姿态和相机画面调整。通过这些条件的仍然是单个候选，尚未执行两两配对。

## 运行与观察

在已有的容器开发终端运行：

```bash
bash /home/rosdev/missing-semester/2027/Wit-1/self-study/opencv/04-light-direction/run.sh --verify
```

脚本会编译、执行检查并打开窗口，不需要启动 ROS master。重开时可以去掉 `--verify`；从其他位置克隆仓库时，在本节目录运行 `bash run.sh`。

程序复用第二课的 HSV 和第三课的轮廓处理头文件，应保留整个 OpenCV 学习目录。构建位于 `~/catkin_ws/.opencv-build/04-light-direction`，日志与输出位于 `~/catkin_ws/records/opencv/04-light-direction`。

| 窗口区域 | 内容 |
| --- | --- |
| 左上 Original | 六根同尺寸红条，分别竖直、左右倾斜和横放 |
| 右上 Red mask | 固定 HSV 规则的结果 |
| 左下 Shape candidates | 黄线为长轴，白线为竖直参考；下方标注编号与实测角度 |
| 右下 Direction passed | 绿框标出满足方向条件的候选；原图仍保留 |
| Max tilt deg | 允许偏离竖直方向的最大角度，默认 15° |

先将滑块从 15 调到 30，观察进入候选的方向与底部 `Direction passed` 数量。之后可调到 65、90，再调回 15。`Shape candidates` 表示只满足面积和长短边比的数量，不随方向门槛改变。

按 S 保存当前结果和 `directions.csv`；按 Q、Esc 或关闭窗口退出。
